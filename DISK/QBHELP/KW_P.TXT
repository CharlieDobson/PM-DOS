#topic PAINT Statement
#key PAINT Statement
PAINT fills an area of a graphics screen with a colour or a pattern.  The
fill starts at a point and spreads out until it meets a border colour.

{b}PAINT{p} [STEP] (x!, y!) [, [paint] [, [bordercolour%] [, background$]]]

    {o} STEP             x! and y! are offsets from the last point drawn.
    {o} x!, y!           Where the fill starts.
    {o} paint            A colour number, or a tile string (see below).
                       Without one, the foreground colour.
    {o} bordercolour%    The colour that stops the fill.  Without one,
                       the paint colour.
    {o} background$      See below.

The fill spreads up, down, left and right, as far as the border colour or
the edge of the viewport.  The border must be closed: one gap lets the
paint out over the rest of the screen.  Nothing is painted when the start
point is outside the viewport or already in the border colour.

A tile string paints a pattern that repeats across and down the area.
Each byte is one row of the pattern, except in the 16-colour modes:
    SCREEN 1          a byte is 4 pixels, 2 bits each
    SCREEN 2, 11      a byte is 8 pixels, 1 bit each
    SCREEN 7-9, 12    4 bytes are a row of 8 pixels: one byte for each
                      bit of the colour number, bit 0 first
    SCREEN 10         2 bytes are a row of 8 pixels, the same way
    SCREEN 13         a byte is 1 pixel: its colour
The tile may be up to 64 bytes long.  An empty tile is "Illegal function
call", and so is PAINT on a text screen.

In QBasic, background$ names a tile row already on the screen that the
fill may paint over.  This QBasic accepts background$ and does not need it.

Example:
    SCREEN 12
    CIRCLE (320, 240), 100, 14
    PAINT (320, 240), 1, 14                ' blue inside the yellow ring
    tile$ = CHR$(&HAA) + CHR$(0) + CHR$(0) + CHR$(0)
    PAINT (5, 5), tile$, 14                ' blue stripes outside it

See Also  [[CIRCLE]]  [[LINE]]  [[DRAW]]  [[COLOR]]  [[SCREEN]]
#topic PALETTE, PALETTE USING Statements
#key PALETTE Statement
#entry PALETTE USING Statement
PALETTE changes the colour an attribute (a colour number the program draws
with) shows on the screen.  PALETTE USING changes all of them from an
array.

{b}PALETTE{p} [attribute%, colour&]
{b}PALETTE USING{p} arrayname[(index%)]

    {o} attribute%       The colour number to change.
    {o} colour&          The colour it is to show (see below).  -1 leaves
                       the attribute as it is.
    {o} arrayname        An INTEGER or LONG array with a colour for each
                       attribute, attribute 0 first.
    {o} index%           The element that holds attribute 0's colour.
                       Without one, the array's first element.

PALETTE with nothing after it puts back the mode's own colours.

What a colour number means depends on the screen mode:
    SCREEN 0            0-63, the EGA colours
    SCREEN 1, 2, 7, 8   0-15, the sixteen standard colours
    SCREEN 9            0-63, the EGA colours
    SCREEN 10           0-8
    SCREEN 11, 12, 13   65536 * blue + 256 * green + red, each 0 to 63

An attribute the mode does not have, or a colour out of range, is
"Illegal function call".  So is an array too short for every attribute.

In this QBasic, PALETTE in SCREEN 0 checks its numbers and changes nothing,
and SCREEN 10's nine colours are steady greys (QBasic makes some blink).

Example:
    SCREEN 13
    FOR i% = 0 TO 63
        PALETTE i%, i%                    ' attributes 0-63: reds
    NEXT i%
    DIM pal&(255): PALETTE USING pal&(0)  ' every attribute black

See Also  [[COLOR]]  [[SCREEN]]  [[Screen Modes|screenmodes]]
#topic PCOPY Statement
#key PCOPY Statement
PCOPY copies one screen page over another.

{b}PCOPY{p} sourcepage%, destinationpage%

    {o} sourcepage%       The page to copy.
    {o} destinationpage%  The page that is overwritten.

The pages a mode has are listed under [[Screen Modes|screenmodes]].  A
page the mode does not have is "Illegal function call".

PCOPY goes with SCREEN's active and visible pages: draw the next picture
on a hidden page, then copy it to the page on show, and the picture
changes at once instead of being seen half drawn.

Example:
    SCREEN 7, , 1, 0                  ' draw on page 1, show page 0
    LINE (0, 0)-(319, 199), 4, BF
    PCOPY 1, 0                        ' the red screen appears at once

See Also  [[SCREEN]]  [[CLS]]
#topic PEEK Function
#key PEEK Function
PEEK returns the byte at an address in the segment set by DEF SEG.

{b}PEEK{p}(address)

    {o} address          The offset in the segment, 0 to 65535.

The result is 0 to 255.  A negative address counts back from 65536; one
outside -32768 to 65535 is "Overflow".

This QBasic has no real-mode memory: PEEK reaches the program's own
variables, the screen at &HB800 and &HA000, the BIOS data area at &H40 and
the ROMs.  Any other address reads 0.  See [[QBasic on PM-DOS|pmdos]].

Example:
    DEF SEG = &H40
    IF PEEK(&H17) AND 64 THEN PRINT "Caps Lock is on"
    DEF SEG

See Also  [[POKE]]  [[DEF SEG|SEG]]  [[VARPTR]]  [[VARSEG]]  [[SADD]]
#topic POKE Statement
#key POKE Statement
POKE writes a byte at an address in the segment set by DEF SEG.

{b}POKE{p} address, byte%

    {o} address          The offset in the segment, 0 to 65535.
    {o} byte%            The value to write.  Only its low 8 bits are
                       stored.

A POKE in the wrong place can change the program's variables without
warning.  An address or value outside -32768 to 65535 is "Overflow".

This QBasic has no real-mode memory: POKE reaches the program's own
variables and the screen at &HB800 (text) and &HA000 (SCREEN 13).  In the
BIOS data area only the keyboard buffer takes a POKE; anything else is
ignored.  See [[QBasic on PM-DOS|pmdos]].

Example:
    DEF SEG = &HB800
    POKE 0, ASC("A")                  ' an A in the top left corner,
    POKE 1, &H1E                      ' yellow on blue
    DEF SEG

See Also  [[PEEK]]  [[DEF SEG|SEG]]  [[VARPTR]]  [[VARSEG]]
#topic PEN Function, PEN Statements
#key PEN Function
#entry PEN Statement
The PEN function reads a light pen.  PEN ON, PEN OFF and PEN STOP control
the trapping of the pen by ON PEN GOSUB.

{b}PEN{p}(n%)
{b}PEN ON{p} | {b}PEN OFF{p} | {b}PEN STOP{p}
{b}ON PEN GOSUB{p} line

    {o} n%               What PEN returns:
                         0     -1 if the pen was pressed since the last
                               PEN(0), else 0
                         1, 2  x and y where the pen was last pressed
                         3     -1 if the pen's switch is down, else 0
                         4, 5  the pen's latest x and y
                         6, 7  row and column where it was last pressed
                         8, 9  the pen's latest row and column
    {o} line             The label or line number of the handler.

n% outside 0-9 is "Illegal function call".

This QBasic has no light pen: PEN(n%) is always 0 and ON PEN never
happens.

See Also  [[event trapping|events]]  [[ON]]  [[STICK]]
#topic PLAY Statement, PLAY Function
#key PLAY Statement
#entry PLAY Function
PLAY plays music on the PC speaker from a string of notes and commands.
The PLAY function returns how many notes are still waiting to be played.

{b}PLAY{p} commandstring$
{b}PLAY{p}(n)
{b}PLAY ON{p} | {b}PLAY OFF{p} | {b}PLAY STOP{p}
{b}ON PLAY{p}(queuelimit%) {b}GOSUB{p} line

    {o} commandstring$   The notes and commands: see [[Music Strings|PLAY-music]].
    {o} n                Any number; it is not used.
    {o} queuelimit%      1 to 32.  The handler runs when fewer notes than
                       this are waiting.
    {o} line             The label or line number of the handler.

At first PLAY returns only when its music has finished.  After MB in a
string the music plays in the background while the program goes on, with
up to 32 notes waiting; PLAY(n) counts them (it is 0 in the foreground).
ON PLAY lets the program add more notes before the queue runs dry; PLAY
ON starts that trapping.  See [[event trapping|events]].

Example:
    PLAY "T160 O3 L8 CDEFGAB > C"
    PLAY "MB L4 C E G"                ' plays while the program goes on
    PRINT PLAY(0); "notes waiting"

See Also  [[Music Strings|PLAY-music]]  [[SOUND]]  [[BEEP]]  [[VARPTR$]]
#topic PLAY Music Strings
#context PLAY-music
The commands in a PLAY string.  They may be in upper or lower case, and
blanks and semicolons between them are ignored.  Octave, length, tempo and
style carry on from one PLAY to the next.

  {b}Notes{p}
    A to G        A note in the current octave.  # or + after the letter
                  makes it sharp, - flat.  A length (1-64) may follow,
                  then dots.
    N n           Note n of the whole range, 1 to 84 (seven octaves of
                  twelve).  N0 is a rest.
    P n           A rest of length n (1-64).
    .             After a note or a rest: half as long again.  Each
                  further dot adds half of what the dot before added.

  {b}Octaves{p}
    O n           The octave, 0 to 6; 4 at the start.  Middle C is the
                  first note of octave 3.
    <  >          One octave down, one octave up.

  {b}Length and tempo{p}
    L n           The length of the notes that follow: 1 a whole note,
                  4 a quarter (the start), up to 64.
    T n           Quarter notes a minute, 32 to 255; 120 at the start.

  {b}Style{p}
    MN            Each note sounds for 7/8 of its length (the start).
    ML            Legato: the whole length.
    MS            Staccato: 3/4 of the length.
    MF            Foreground: PLAY waits until the music has finished.
    MB            Background: the program goes on; up to 32 notes wait.

  {b}Variables{p}
    X + VARPTR$(a$)   Plays the string a$ here.
    = + VARPTR$(v%)   Any number may be a variable's instead, as in
                      "T=" + VARPTR$(speed%).

A number out of range, or a letter that is no command, is "Illegal
function call".

Example:
    PLAY "T200 L16 O4 CDEC CDEC L8 EFG EFG"
    tune$ = "L8 GFEDC4"
    PLAY "O3 X" + VARPTR$(tune$)

See Also  [[PLAY]]  [[SOUND]]  [[VARPTR$]]
#topic PMAP Function
#key PMAP Function
PMAP converts a coordinate between the units WINDOW set (logical) and the
pixels of the viewport (physical).

{b}PMAP{p}(coordinate#, n%)

    {o} coordinate#      The coordinate to convert.
    {o} n%               0  logical x to physical x
                       1  logical y to physical y
                       2  physical x to logical x
                       3  physical y to logical y

Physical coordinates count pixels from the viewport's top left corner.
With no WINDOW set the two kinds are the same.  n% outside 0-3, or PMAP on
a text screen, is "Illegal function call".

Example:
    SCREEN 12
    WINDOW (-10, -10)-(10, 10)
    PRINT PMAP(0, 0); PMAP(0, 1)      ' where (0, 0) is, in pixels

See Also  [[WINDOW]]  [[VIEW]]  [[POINT]]
#topic POINT Function
#key POINT Function
POINT returns the colour of a pixel, or where the last point drawn is.

{b}POINT{p}(x!, y!)
{b}POINT{p}(n%)

    {o} x!, y!           The pixel, in the current coordinates (WINDOW's
                       when one is set).
    {o} n%               0  the last point's x, in pixels
                       1  its y, in pixels
                       2  its x in WINDOW's units
                       3  its y in WINDOW's units

POINT(x!, y!) is -1 for a pixel outside the viewport.  Pixels are counted
from the viewport's top left corner; with no WINDOW set, POINT(2) and
POINT(3) are the same as POINT(0) and POINT(1).  POINT on a text screen is
"Illegal function call".

Example:
    SCREEN 13
    PSET (100, 50), 4
    PRINT POINT(100, 50)              ' 4
    PRINT POINT(0); POINT(1)          ' 100  50

See Also  [[PSET]]  [[PMAP]]  [[WINDOW]]  [[VIEW]]

#topic PSET, PRESET Statements
#key PSET Statement
#key PRESET Statement
PSET sets a pixel to a colour.  PRESET does the same, but without a colour
it uses the background colour, which rubs the pixel out.

{b}PSET{p} [STEP] (x!, y!) [, colour%]
{b}PRESET{p} [STEP] (x!, y!) [, colour%]

    {o} STEP             x! and y! are offsets from the last point.
    {o} x!, y!           The pixel, in the current coordinates.
    {o} colour%          The colour.  Without one, PSET uses the
                       foreground colour and PRESET the background (0).

The pixel becomes the last point, which STEP, LINE and DRAW start from.
A pixel outside the viewport is not drawn.  PSET or PRESET on a text
screen is "Illegal function call".

Example:
    SCREEN 12
    FOR x% = 0 TO 639
        PSET (x%, 240 - 100 * SIN(x% / 50)), 10
    NEXT x%

See Also  [[POINT]]  [[LINE]]  [[CIRCLE]]  [[COLOR]]  [[SCREEN]]
#topic PRINT, LPRINT Statements
#key PRINT Statement
#key LPRINT Statement
#key ?
PRINT writes numbers and strings on the screen, or into a file.  LPRINT
writes them on the printer.

{b}PRINT{p} [#filenumber%,] [expressionlist] [{; | ,}]
{b}LPRINT{p} [expressionlist] [{; | ,}]

    {o} filenumber%      A file opened for OUTPUT or APPEND.  Without
                       one, PRINT writes on the screen.
    {o} expressionlist   The items to write, with ; or , between them.
    {o} ;                The next item follows straight on.
    {o} ,                The next item starts at the next zone of 14
                       columns.

A number is written with a blank before it (or its minus sign) and a blank
after it.  A list that ends with ; or , does not end the line; any other
list does.  PRINT on its own writes an empty line.  An item
that would run past the end of the line goes whole to the next line,
unless it is longer than a line.  [[TAB]] and [[SPC]] may be put among the
items to move along the line.

? may be typed for PRINT; the editor changes it to PRINT.  LPRINT with no
printer is "Device unavailable".

Example:
    PRINT "Total:"; 12 * 3
    PRINT "Name", "Age"
    OPEN "LOG.TXT" FOR APPEND AS #1
    PRINT #1, DATE$; " "; TIME$
    CLOSE #1

See Also  [[PRINT USING|USING]]  [[WRITE]]  [[WIDTH]]  [[LOCATE]]  [[OPEN]]
#topic PRINT USING, LPRINT USING Statements
#key USING
#entry PRINT USING Statement
#entry LPRINT USING Statement
PRINT USING writes numbers and strings laid out by a format string.
LPRINT USING does the same on the printer.

{b}PRINT{p} [#filenumber%,] {b}USING{p} format$; expressionlist [{; | ,}]
{b}LPRINT USING{p} format$; expressionlist [{; | ,}]

    {o} filenumber%      A file opened for OUTPUT or APPEND.
    {o} format$          Text with fields in it (see below).
    {o} expressionlist   The values, with ; or , between them; here the
                       two mean the same.  A ; or , at the end leaves
                       the cursor on the line.

Each value takes the format's text up to the next field, then fills the
field.  When the format runs out it starts again from the left.  After
the last value, the text up to the next field is written too.

  {b}Number fields{p}
    #        A digit.
    .        The decimal point: ##.## writes two decimals, rounded.
    ,        Before the point: the digits in groups of three, with commas.
    +        At the start or the end: the number's sign, + or -.
    -        At the end: a minus after a negative number.
    $$       A dollar sign just before the first digit.
    **       The blanks in front of the number filled with asterisks.
    **$      Both of these.
    ^^^^     An exponent, E+nn (D+nn for a DOUBLE); ^^^^^ gives E+nnn.

  {b}String fields{p}
    !        The string's first character.
    &        The whole string.
    \   \    As many characters as the field is wide, both backslashes
             counted; each blank between them adds one.

  {b}Others{p}
    _        Writes the next character as it is: _# writes #.

A number too big for its field is written whole, with % in front of it.
A value of the wrong kind for its field is "Type mismatch"; a format with
no field in it, or a number field over 24 characters, is "Illegal
function call".

Example:
    PRINT USING "##.##"; 3.14159              ' 3.14
    PRINT USING "$$#,###.##"; 1234.5          ' $1,234.50
    PRINT USING "\  \ is ##"; "Annette"; 7    ' Anne is  7

See Also  [[PRINT]]  [[WRITE]]  [[STR$]]  [[PALETTE USING|PALETTE]]
#topic RANDOMIZE Statement
#key RANDOMIZE Statement
RANDOMIZE starts the random-number generator at a new place, so that RND
gives a different series of numbers.

{b}RANDOMIZE{p} [seed]

    {o} seed             Any number.  Without one, RANDOMIZE asks for a
                       seed from -32768 to 32767 on the screen.

Every run starts the generator in the same state, so a program without
RANDOMIZE gets the same numbers from RND each time.  RANDOMIZE TIMER takes
the seed from the clock, which differs from run to run.

The seed changes only part of the generator's state, so the same seed
does not always give the same series.  To repeat a series, use RND(-1)
before each RANDOMIZE.

Example:
    RANDOMIZE TIMER
    die% = INT(RND * 6) + 1
    PRINT "You threw a"; die%

See Also  [[RND]]  [[TIMER]]
#topic READ Statement
#key READ Statement
READ takes items from the program's DATA statements into variables.

{b}READ{p} variablelist

    {o} variablelist     Variables, separated by commas.  Each takes the
                       next DATA item.

The items are taken in order, from the first DATA statement in the program
to the last.  DATA belongs to the module-level code, and a READ in a SUB or
FUNCTION reads the same items.  [[RESTORE]] sets where reading goes on.

A string variable takes any item, as text.  A numeric variable needs an
item that is a number (an empty item reads as 0): anything else is
"Syntax error", shown at the DATA statement.  A number too big for the
variable is "Overflow".  Reading past the last item is "Out of DATA".

Example:
    FOR i% = 1 TO 3
        READ who$, age%
        PRINT who$; age%
    NEXT i%
    DATA Ann, 34, Bob, 27, "Smith, J", 51

See Also  [[DATA]]  [[RESTORE]]
#topic REM Statement
#key REM Statement
REM makes the rest of the line a remark, which QBasic skips when the
program runs.

{b}REM{p} remark
{b}'{p} remark

    {o} remark           Any text, up to the end of the line.

An apostrophe (') does the same as REM, and can follow a statement
directly; after a statement, REM needs a colon before it.  The
metacommands $DYNAMIC and $STATIC are written in remarks: see
[[Metacommands|meta]].

Example:
    REM The area of a circle
    r = 5                             ' the radius
    area = 3.141593 * r ^ 2: REM pi r squared

See Also  [[Metacommands|meta]]
#topic RESET Statement
#key RESET Statement
RESET closes every open file and device, and writes out what is waiting
in their buffers.

{b}RESET{p}

RESET does the same as CLOSE with no file numbers.  The printer that
LPRINT uses is closed too.

Example:
    OPEN "A.TXT" FOR OUTPUT AS #1
    OPEN "B.TXT" FOR OUTPUT AS #2
    RESET                             ' both files are closed

See Also  [[CLOSE]]  [[OPEN]]  [[END]]
#topic RESTORE Statement
#key RESTORE Statement
RESTORE sets which DATA item the next READ takes.

{b}RESTORE{p} [line]

    {o} line             A line number or label.  The next READ takes the
                       first item of the first DATA statement at or
                       after it.  Without one, the first DATA item in
                       the program.

Example:
    READ a%, b%
    RESTORE
    READ c%                           ' c% is 10, the same as a%
    DATA 10, 20

See Also  [[READ]]  [[DATA]]
#topic RESUME Statement
#key RESUME Statement
RESUME ends an error handler and says where the program goes on.

{b}RESUME{p} [0]
{b}RESUME NEXT{p}
{b}RESUME{p} line

    {o} 0                The same as RESUME alone: the statement that
                       failed runs again.
    {o} NEXT             The program goes on with the statement after
                       the one that failed.
    {o} line             The program goes on at this line number or
                       label.

ERR goes back to 0.  RESUME when no error is being handled is "RESUME
without error".

Example:
    ON ERROR GOTO NoFile
    OPEN "DATA.TXT" FOR INPUT AS #1
    END
    NoFile:
    OPEN "DATA.TXT" FOR OUTPUT AS #1: CLOSE #1   ' make an empty one
    RESUME                                       ' and try again

See Also  [[ON ERROR|ON-ERROR]]  [[ERR]]  [[ERL]]  [[ERROR]]  [[Run-Time Error Codes|errcodes]]
#topic RND Function
#key RND Function
RND returns a random number from 0 up to, but not including, 1.

{b}RND{p}[(n!)]

    {o} n!               Above 0, or left out: the next number of the
                       series.  0: the last number again.  Below 0: a
                       number that depends on n! alone, and a new
                       series that starts from it.

The series is the same in every run unless the program uses RANDOMIZE.
A whole number from low% to high% is INT(RND * (high% - low% + 1)) + low%.

Example:
    RANDOMIZE TIMER
    FOR i% = 1 TO 5
        PRINT INT(RND * 100) + 1;     ' five numbers from 1 to 100
    NEXT i%

See Also  [[RANDOMIZE]]  [[INT]]
#topic RUN Statement
#key RUN Statement
RUN starts the program again from the beginning, or loads another program
and runs that.

{b}RUN{p} [{linenumber | file$}]

    {o} linenumber       The line of the module to start at.
    {o} file$            The program to load and run.  .BAS is added to
                       a name that has no extension.

RUN closes every file and clears every variable before it starts.  With
file$, the program in memory is replaced; QBasic asks first whether to
save changes to it.  A file$ that is not there is "File not found", and a
linenumber the module does not have is "Label not defined".

Example:
    INPUT "Again (Y/N)"; a$
    IF UCASE$(a$) = "Y" THEN RUN
    RUN "MENU"                        ' loads and runs MENU.BAS

See Also  [[CHAIN]]  [[END]]  [[SYSTEM]]  [[CLEAR]]
#topic SADD Function
#key SADD Function
SADD returns the offset of the characters of a string variable.

{b}SADD{p}(stringvariable$)

    {o} stringvariable$  A variable-length string.  A fixed-length string
                       is "Type mismatch": use VARPTR for one.

The characters are in the default data segment, the one DEF SEG sets
when it is given no segment.  The offset is an INTEGER, so one above
32767 comes out negative.  It holds only until the string is changed: a
new value is kept somewhere else.

Example:
    a$ = "Hello"
    DEF SEG                           ' the default data segment
    PRINT CHR$(PEEK(SADD(a$)))        ' H

See Also  [[VARPTR]]  [[VARSEG]]  [[PEEK]]  [[DEF SEG|SEG]]
#topic SCREEN Statement
#key SCREEN Statement
SCREEN sets the screen mode, and which page the program writes on and
which page is shown.

{b}SCREEN{p} [mode%] [, [colourswitch%] [, [activepage%] [, visualpage%]]]

    {o} mode%            The screen mode: see [[Screen Modes|screenmodes]].
    {o} colourswitch%    Colour on or off on old CGA monitors.  It
                       changes nothing on an EGA or VGA.
    {o} activepage%      The page PRINT and the drawing statements write
                       on.
    {o} visualpage%      The page shown.  Without one, the active page.

A different mode clears the screen, sets its text size, and puts back its
colours and palette; VIEW and WINDOW are turned off and both pages are 0.
A mode or a page the screen does not have is "Illegal function call".

Drawing on a page that is not shown, and then showing it (or copying it
with PCOPY), changes the whole picture at once.

SCREEN 3 and 4 (Hercules, Olivetti) are not in this QBasic.

Example:
    SCREEN 12                         ' 640 x 480, 16 colours
    CIRCLE (320, 240), 100, 14
    SLEEP
    SCREEN 0                          ' back to text
    WIDTH 80, 25

See Also  [[Screen Modes|screenmodes]]  [[SCREEN function|SCREEN-function]]  [[PCOPY]]
          [[COLOR]]  [[PALETTE]]  [[WIDTH]]  [[VIEW]]  [[WINDOW]]
#topic Screen Modes
#context screenmodes
#entry Screen Modes
The modes SCREEN sets.  Attributes are the colour numbers a program draws
with; colours are how many PALETTE can choose from for them.

  Mode  Pixels    Text columns x rows     Attributes  Colours  Pages
    0   -         40 or 80 x 25, 43, 50       16          64   0-7
    1   320x200   40 x 25                      4          16   0
    2   640x200   80 x 25                      2          16   0
    7   320x200   40 x 25                     16          16   0-7
    8   640x200   80 x 25                     16          16   0-3
    9   640x350   80 x 25 or 43               16          64   0-1
   10   640x350   80 x 25 or 43                4           9   0-1
   11   640x480   80 x 30 or 60                2     262,144   0
   12   640x480   80 x 30 or 60               16     262,144   0
   13   320x200   40 x 25                    256     262,144   0

SCREEN 0 is text only; with 43 or 50 rows of 80 columns it has pages 0-3.
SCREEN 10 is for a monochrome monitor.  WIDTH chooses between the numbers
of rows.  Characters are 8 pixels wide; they are 8 high, but 14 in
SCREEN 9 and 10 at 25 rows and 16 in SCREEN 11 and 12 at 30 rows.

QBasic needs an EGA for modes 7 to 10 and a VGA for 11 to 13.  This
QBasic shows every graphics mode through a VGA mode, so it needs a VGA for
all of them.

#topic SELECT CASE Statement
#key SELECT
#entry SELECT CASE Statement
#key CASE
#key IS
SELECT CASE runs one of several blocks of statements, chosen by the value
of an expression.

{b}SELECT CASE{p} testexpression
{b}CASE{p} expressionlist1
    [statementblock-1]
[{b}CASE{p} expressionlist2
    [statementblock-2]]...
[{b}CASE ELSE{p}
    [statementblock-n]]
{b}END SELECT{p}

    {o} testexpression   A number or a string.
    {o} expressionlist   One or more of these, with commas between:
                         expression
                         expression {b}TO{p} expression
                         {b}IS{p} relational-operator expression
    {o} statementblock   The statements to run when the list matches.

The CASEs are tried in order.  The first one whose list matches the value
runs its block, and the program goes on after END SELECT.  CASE ELSE, if
there is one, comes last and runs when no other CASE matches.

In a TO range the smaller value comes first.  IS takes =, <>, <, <=, >
or >=.  Strings compare by their character codes.  When the test value is
an INTEGER or LONG, a CASE value with a fraction is rounded first.

Example:
    SELECT CASE score%
        CASE IS < 0, IS > 100: PRINT "Not a score"
        CASE 90 TO 100: PRINT "A"
        CASE 50 TO 89: PRINT "Pass"
        CASE ELSE: PRINT "Fail"
    END SELECT

See Also  [[IF]]  [[ON...GOTO|ON-GOTO]]  [[Boolean Operators|boolean]]

                       limit.
    {o} rows%            25, 43 or 50 in SCREEN 0.  For the graphics
                       modes see [[Screen Modes|screenmodes]].
    {o} filenumber%      An open file.
    {o} device$          "SCRN:", or a printer such as "LPT1:".

A new size clears the screen.  In SCREEN 0, 43 rows need an EGA or VGA and
50 rows a VGA; a graphics mode's columns are fixed.  A size the screen
cannot have is "Illegal function call".

Example:
    WIDTH 40                          ' big letters
    WIDTH 80, 50                      ' 50 rows on a VGA
    WIDTH LPRINT 132

See Also  [[SCREEN]]  [[Screen Modes|screenmodes]]  [[PRINT]]  [[VIEW PRINT|VIEW-PRINT]]
#topic WINDOW Statement
#key WINDOW Statement
WINDOW gives the graphics viewport coordinates in units of the program's
choosing.

{b}WINDOW{p} [[SCREEN] (x1!, y1!)-(x2!, y2!)]

    {o} SCREEN           y grows downwards, as on the screen.  Without
                       SCREEN, y grows upwards, as on a graph.
    {o} (x1!, y1!)       One corner of the area, in the new units.
    {o} (x2!, y2!)       The opposite corner.

The area is fitted to the viewport.  PSET, LINE, CIRCLE, PAINT, POINT and
the other drawing statements then take coordinates in the new units, and
PMAP converts between them and pixels.  WINDOW alone goes back to pixels.
Two equal x or y values, or WINDOW on a text screen, are "Illegal function
call".

Example:
    SCREEN 12
    WINDOW (-10, -10)-(10, 10)        ' (0, 0) is in the middle
    LINE (-10, 0)-(10, 0)             ' the x axis
    FOR x = -10 TO 10 STEP .05: PSET (x, x * x / 10): NEXT x

See Also  [[VIEW]]  [[PMAP]]  [[POINT]]  [[SCREEN]]
#topic WRITE Statement
#key WRITE Statement
WRITE writes values on the screen or into a file in a form INPUT # reads
back: commas between them and strings in quotes.

{b}WRITE{p} [#filenumber%,] [expressionlist]

    {o} filenumber%      A file opened for OUTPUT or APPEND.  Without
                       one, WRITE writes on the screen.
    {o} expressionlist   The numbers and strings to write, with commas
                       between them.

Numbers are written without the blanks PRINT puts round them.  The line
always ends after the last item; WRITE alone writes an empty line.

Example:
    OPEN "PEOPLE.TXT" FOR OUTPUT AS #1
    WRITE #1, "Smith, J", 42, 1.5     ' "Smith, J",42,1.5
    CLOSE #1

See Also  [[PRINT]]  [[INPUT]]  [[OPEN]]
