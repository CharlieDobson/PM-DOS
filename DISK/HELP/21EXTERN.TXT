#! 21EXTERN.TXT - the external commands, HELP to XCOPY.
#topic HELP|Help
Starts PM-DOS Help: this program.

{b}Syntax{p}

    HELP [topic]

{b}Parameters{p}

topic
    The command or CONFIG.SYS statement to open at.  With none, the
    contents.

{b}Related Commands{p}

Every command answers /? with a short account of itself: DIR /?.  For
how this program is used, see [[How to Use PM-DOS Help|Help on Help]].
#notes
{b}Where the text is{p}

Help text comes from HELP.HLP.  HELP prints an error message and
exits if the file cannot be found.

{b}Changing the text{p}

HELP.HLP is plain text in the layout Microsoft's HELPMAKE took: EDIT
can change it.  A topic starts with one or more .context lines naming
it, a .topic line with its title, and .freeze with how many lines
stay at the top; then its text.  In the text, \b and \p turn bold on
and off, \i and \p the link colour, and a link is written as
\aWORDS\vNAME\v, with the brackets round it typed as they are.

On the PM-DOS source disk the file is made from the parts in
DISK\HELP by TOOLS\MKHELP.PL, which also checks that every link leads
to a topic.

{b}The exit code{p}

0, or 1 when HELP.HLP was not found or could not be read.
#examples
To read about COPY:

    help copy

To open at the contents:

    help
#topic IPCONFIG|Ipconfig
Shows the computer's TCP/IP settings, and gives back or renews the IP
address a DHCP server lent it.

{b}Syntax{p}

    IPCONFIG [/ALL | /RELEASE | /RENEW]

{b}Switches{p}

/ALL
    Also shows the computer's name, the network card's physical
    address, the DHCP, DNS and WINS servers, and when the lease was
    obtained and when it expires.

/RELEASE
    Gives the IP address back to the DHCP server.  The computer has no
    address until IPCONFIG /RENEW is used or the computer is restarted.

/RENEW
    Renews the lease, or asks for a new address if there is none.
    IPCONFIG waits up to 10 seconds for the answer.

{b}Related Commands{p}

The address comes from [[TCPIP.SYS]], which is loaded with [[DEVICE=]].
#notes
{b}Where the address comes from{p}

TCPIP.SYS asks a DHCP server for an address when CONFIG.SYS runs.  If
no answer comes in time, TCPIP.SYS keeps asking in the background, so
IPCONFIG may show an address that arrived later.

TCPIP.SYS renews the lease itself when half of it has passed.  If the
server does not answer, any DHCP server is asked near the end of the
lease.  When the lease runs out, the address is dropped and a new one
is asked for.

{b}A fixed address{p}

An address set with TCPIP.SYS /IP= has no lease.  /RELEASE and /RENEW
say so and change nothing.

{b}The exit code{p}

0, or 1 when TCPIP.SYS is not loaded, a switch is wrong, or the address
could not be released or renewed.
#examples
To see the address:

    IPCONFIG

To see every setting:

    IPCONFIG /ALL

To ask the DHCP server for the address again:

    IPCONFIG /RENEW
#topic ISAPNP|Isapnp
Lists the ISA Plug and Play cards in the machine, and switches their
devices on.

{b}Syntax{p}

    ISAPNP
    ISAPNP /A
    ISAPNP card.device [IO=port[,port ...]] [IRQ=n[,n]] [DMA=n[,n]]
           [MEM=address[,address ...]] [ON | OFF]

ISAPNP on its own lists every card and every device on it, and what
each is using now.

{b}Parameters{p}

card.device
    The device to set, numbered as the list numbers it: 1.0 is the
    first device on the first card.  Given resources, the device is
    given those and switched on; ON or OFF alone switches it as it is.

IO=port
    The port, or ports, in hexadecimal: IO=220.

IRQ=n
    The interrupt line, in decimal.

DMA=n
    The DMA channel, in decimal.

MEM=address
    A memory window, in hexadecimal.

{b}Switches{p}

/A
    Switches on every device that is off, giving each the first set of
    resources it offers in which nothing collides with anything the
    machine is known to be using.

{b}Related Commands{p}

To see what the machine is using, see [[PMD]].
#notes
{b}Why it is needed{p}

A Plug and Play card starts with every device on it off.  A machine
with a Plug and Play BIOS switches them on before PM-DOS starts; a
486 with an ISA bus usually has no such BIOS, and this program does
the job the card's own setup program did under MS-DOS.  The kernel
switches on only what it needs itself, an IDE port for a CD-ROM.

{b}What /A knows is taken{p}

The ports every PC has, the serial and printer ports and their lines,
the lines PCI cards use, the lines and channels the kernel keeps, and
what the other Plug and Play devices hold.  A card that is not Plug
and Play cannot be seen: give a device its resources by hand when one
of them is taken.  Memory windows are never chosen by /A.

{b}When to run it{p}

From AUTOEXEC.BAT, before the programs that use the cards.
#examples
To see the cards:

    isapnp

To switch everything on:

    isapnp /a

To give a sound card's first device the classic settings:

    isapnp 1.0 io=220 irq=5 dma=1,5
#topic KEYB|Keyb
Loads a keyboard layout for another country.

{b}Syntax{p}

    KEYB [xx[,[page][,file]]] [/ID:nnn]

Type KEYB on its own to see which layout is in use.

{b}Parameters{p}

xx
    The two letters of the layout:

    BE  Belgium            IT  Italy              SF  Switzerland, French
    BR  Brazil             LA  Latin America      SG  Switzerland, German
    CF  Canada, French     NL  Netherlands        SL  Slovakia
    CZ  Czech Republic     NO  Norway             SP  Spain
    DK  Denmark            PL  Poland             SU  Finland
    DV  US Dvorak          PO  Portugal           SV  Sweden
    FR  France             RU  Russia             TR  Turkey
    GK  Greece             UK  United Kingdom     US  United States
    GR  Germany            HU  Hungary            YU  Yugoslavia
    IS  Iceland

page
    The code page to use the layout in.  Without one, the code page in
    use.

file
    The file of layouts.  Without one, KEYBOARD.SYS where the system's
    files are.

{b}Switches{p}

/ID:nnn
    Which keyboard, for a country that has two: /ID:142 is the second
    Italian layout, /ID:457 the Polish programmer's, /ID:440 the
    Turkish F layout.

{b}Related Commands{p}

For the country's dates and letters, see [[COUNTRY]]; for the code
page, see [[CHCP]].  See also [[International Commands|International]].
#notes
{b}Nothing stays resident{p}

KEYB hands the layout to the kernel, which owns the keyboard, and
ends.  It goes in AUTOEXEC.BAT, not in CONFIG.SYS.

{b}Switching back{p}

Ctrl+Alt+F1 switches to the US keyboard and Ctrl+Alt+F2 back to the
layout, while it stays loaded.  KEYB US loads the built-in US layout
for good.

{b}After CHCP{p}

Run KEYB again after changing the code page, so that the layout
matches it.

{b}The file{p}

KEYBOARD.SYS is PM-DOS's own; MS-DOS's file is a different one and is
refused.

{b}The exit code{p}

0 when the layout loaded; 1 for a bad command line or a layout or
code page the file has not got; 2 when the file is missing or is not
a KEYBOARD.SYS.
#examples
To load the German layout:

    keyb gr

To load it for code page 850:

    keyb gr,850

To load the second Italian layout:

    keyb it,,/id:142
#topic LABEL|Label
Makes, changes or removes a disk's volume label.

{b}Syntax{p}

    LABEL [drive:][label]

With no label, LABEL shows the label the disk has and asks for a new
one.  ENTER with nothing typed asks whether to delete the old label.

{b}Parameters{p}

drive:
    The drive.  The current one if none is given.

label
    The new label, up to eleven characters.

{b}Related Commands{p}

To see a label, see [[VOL]] or [[DIR]].  FORMAT /V sets one when the
disk is formatted: see [[FORMAT]].
#notes
{b}What a label may hold{p}

Letters, digits, spaces and most punctuation.  Not * ? / \ | . , ; :
+ = [ ] < > or quotes.

{b}exFAT drives{p}

On exFAT drives, the label keeps the upper and lower case it was
typed with.  VOL and DIR show the label in upper case.

{b}Network drives{p}

A network drive's label cannot be changed from here.
#examples
To label drive A:

    label a: letters

To be asked:

    label
#topic MEM|Mem
Shows how much memory the machine has, and what is using it.

{b}Syntax{p}

    MEM [/DEBUG | /FREE]

Type MEM on its own for the summary: conventional, upper, extended
and expanded memory, how much of each is free, and the largest
program that will fit.

{b}Switches{p}

/DEBUG or /D
    Lists every block in the DOS arena and in upper memory, with its
    owner and size.  Also lists the 32-bit drivers loaded with
    DEVICE= and how much memory each one uses.

/FREE or /F
    Lists the free blocks only.

{b}Related Commands{p}

To put a program in upper memory, see [[LOADHIGH]]; to set upper
memory up, see [[DOS]].  For expanded memory, see [[EMS=]].
#notes
{b}What the numbers mean{p}

Conventional memory is the 640K DOS programs run in.  Upper memory is
the blocks between 640K and 1MB that DOS=UMB sets up.  Extended
memory is everything above 1MB, which the kernel, the cache and
32-bit programs use; expanded memory is what EMS= gives DOS
programs.

{b}The kernel is not in the 640K{p}

PM-DOS runs above the first megabyte, so nearly all of conventional
memory is free for DOS programs.  The 32-bit commands run above it
too and never appear in MEM's list.

{b}32-bit drivers{p}

A 32-bit driver such as RAMDISK.SYS or a network card driver also
loads above 1MB and takes no conventional memory.  MEM /D shows two
sizes for each one: the driver itself, and the memory it set aside
after loading, such as the contents of a RAM disk.
#examples
To see the summary:

    mem

To see who has what, a screen at a time:

    mem /d | more
#topic MODE|Mode
Sets up the printer ports, the serial ports, the screen and the
keyboard, and shows how they are set.

{b}Syntax{p}

    MODE [device] [/STATUS]
    MODE LPTn[:] [COLS=c] [LINES=l] [RETRY=r]
    MODE LPTn[:]=COMm[:]
    MODE COMm[:] [BAUD=b] [PARITY=p] [DATA=d] [STOP=s] [RETRY=r]
    MODE CON[:] [COLS=c] [LINES=n] [RATE=r DELAY=d]
    MODE display[,n]
    MODE device CP [/STATUS | SELECT=yyy | REFRESH]
    MODE device CP PREPARE=((yyy[...]) [drive:][path]filename)

The short forms MS-DOS took also work, with the values in order and
commas between them: MODE LPT1:132,8,P and MODE COM1:96,N,8,1,P.

{b}Parameters{p}

device
    LPT1 to LPT3, PRN, COM1 to COM4 or CON.  With none, MODE shows the
    settings of all of them.

COLS=c (printer)
    80 or 132 characters to the line.

LINES=l (printer)
    6 or 8 lines to the inch.

RETRY=r
    What to do when a printer or a serial port times out.  E, B, R and
    P all keep sending until the port takes the data; E, B and R also
    decide what a program asking whether the port is busy is told
    (error, busy or ready).  CTRL+BREAK stops the waiting.  N or NONE
    turns retrying off.  This is the default setting.

BAUD=b
    110, 150, 300, 600, 1200, 2400, 4800, 9600, 19200, 38400, 57600 or
    115200.  Up to 19200 the first two digits are enough: 96 is 9600.

PARITY=p
    N (none), E (even), O (odd), M (mark) or S (space).  Default is E.

DATA=d
    5, 6, 7 or 8 data bits.  Default is 7.

STOP=s
    1, 1.5 or 2 stop bits.  Default is 1, or 2 at 110 baud.

COLS=c (screen)
    40 or 80 columns.

LINES=n (screen)
    25, 43 or 50 lines.  43 needs an EGA or VGA, and 50 a VGA.

RATE=r
    How fast a held-down key repeats, from 1 to 32.  32 is the fastest.

DELAY=d
    1 to 4 quarter seconds before a held-down key starts to repeat.
    RATE and DELAY have to be given together.

display
    40 or 80 for the columns, or BW40, BW80, CO40, CO80 or MONO for
    the screen mode.  MONO and the others also choose between a
    monochrome and a colour adapter when the machine has both.  ,n
    sets the lines, as LINES= does.

yyy
    A code page number.

{b}Switches{p}

/STATUS or /STA
    Shows the settings without changing anything.

{b}Related Commands{p}

To set the keyboard repeat when the machine starts, see [[KEYRATE=]].
To change the country's code page, see [[CHCP]].
#notes
{b}Nothing stays in memory{p}

On MS-DOS, rerouting a printer or setting RETRY= left part of MODE in
memory.  On PM-DOS the kernel keeps these settings, so MODE loads
nothing.  The settings last until the machine is restarted.  They do
not apply in Windows.

{b}Printing to a serial port{p}

After MODE LPT1=COM1, everything sent to LPT1 or PRN goes out on COM1,
including from DOS programs that use the printer BIOS directly.  Set
the serial port up first with MODE COM1.  MODE LPT1 on its own sends
LPT1 back to the printer port.

{b}The screen and ANSI.SYS{p}

When [[ANSI.SYS]] is loaded, MODE changes the screen through it.
Without it, PM-DOS changes the screen itself, so MODE CON LINES= works
without ANSI.SYS.

{b}Code pages{p}

PM-DOS has no DISPLAY.SYS or PRINTER.SYS, so the CP options report
that the device does not support code pages.  CHCP changes the code
page for the country and the keyboard.

{b}Shifting the screen{p}

MODE display,R and MODE display,L moved the picture on old CGA
monitors.  PM-DOS cannot do this and always says it is unable to shift
the screen.

{b}The exit code{p}

0, or 1 when MODE did not accept the command or a setting failed.
#examples
To set COM1 to 9600 baud, no parity, 8 data bits and 1 stop bit:

    mode com1:96,n,8,1

To print on a serial printer on COM2:

    mode com2:96,n,8,1,p
    mode lpt1=com2

To show 50 lines on a VGA screen:

    mode con lines=50

To make a held-down key repeat as fast as it can:

    mode con rate=32 delay=1

To see every setting:

    mode
#topic MORE|More
Shows output one screen at a time.

{b}Syntax{p}

    MORE [drive:][path]filename
    MORE < [drive:][path]filename
    command | MORE

{b}Parameters{p}

[drive:][path]filename
    A file to show.

command
    A command whose output is to be shown.

{b}Related Commands{p}

To show a file without pausing, see [[TYPE]].
#notes
{b}The pause{p}

After each screenful MORE shows "-- More --" and waits for a key.
Ctrl+C stops it.

{b}The file name{p}

Use double quotes for files with long names.
#examples
To read a file a screen at a time:

    more readme.txt

To page a long listing:

    dir /s | more
#topic MOUNT|Mount
Gives a file a drive letter: a diskette image, a hard disk image or a
CD-ROM image can be read like the disk it came from.

{b}Syntax{p}

    MOUNT
    MOUNT [drive:] file [/R]
    MOUNT /U drive:

MOUNT on its own lists what is mounted.

{b}Parameters{p}

drive:
    The letter to give the file.  Without one, the next free letter.

file
    The image file.

{b}Switches{p}

/R
    Read-only.  An .ISO is read-only anyway.

/U drive:
    Unmounts the drive and gives the letter back.

{b}Related Commands{p}

For the CD-ROM drives themselves, see [[CDEX]].
#notes
{b}What is in the file decides{p}

A file is read as whatever it holds, not as its name says: an
ISO9660 or UDF disc image, a FAT diskette or partition image, or a
whole-disk image with a partition table, whose first FAT partition
becomes the drive.  .ISO, .IMG, .IMA and .DSK are the usual names.

{b}Writing{p}

A mounted FAT image can be written to unless /R was given; the file
changes with it.

{b}Under Windows{p}

Mounted drives are not there while Windows runs.
#examples
To read a CD-ROM image as drive E:

    mount e: c:\images\disc.iso

To mount a diskette image on the next free letter, read-only:

    mount boot.img /r

To let go of E:

    mount /u e:
#topic MOVE|Move
Moves files to another directory or drive, and renames files and
directories.

{b}Syntax{p}

    MOVE [/Y | /-Y] [drive:][path]filename1[,...] destination
    MOVE [/Y | /-Y] [drive:][path]dirname1 dirname2

{b}Parameters{p}

[drive:][path]filename1
    The file or files to move.  Wildcards name several, and several
    names are separated with commas.

destination
    Target location for a drive, a directory, or both.  Moving one file,
    the destination can be a new name for it.

[drive:][path]dirname1
    A directory to rename.

dirname2
    New directory name.

{b}Switches{p}

/Y
    Replaces a file at the destination without asking.

/-Y
    Asks before replacing one.  This is what MOVE does unless /Y is
    given or COPYCMD holds /Y.

{b}Related Commands{p}

To copy instead of moving, see [[COPY]] and [[XCOPY]].  To rename
without moving, see [[REN]].
#notes
{b}On one drive, nothing is copied{p}

A file moved within a drive is moved by changing the directories, in
the time it takes to write two sectors, however big it is.

{b}Across drives{p}

Between two drives the file is copied and then deleted, and the
source is deleted only once the copy is complete.  Anything that goes
wrong before that removes the part-written copy and leaves the source
alone.

{b}Directories{p}

A directory can be renamed, but not moved to another drive.

{b}The exit code{p}

0 when every file was moved, 1 otherwise.
#examples
To move every .DOC file to \LETTERS:

    move *.doc \letters

To move a file to another drive under a new name:

    move report.doc d:\archive\report1.doc

To rename a directory:

    move oldname newname
#topic NETBEUI.SYS|Netbeui.sys
Loads the NetBEUI network protocol, which older Windows networks use
without TCP/IP.

{b}Syntax{p}

    DEVICE=[drive:][path]NETBEUI.SYS [/NAME=name]

{b}Parameters{p}

[drive:][path]
    Location of the NETBEUI.SYS file.

{b}Switches{p}

/NAME=name
    This computer's name on the network, up to 15 letters and digits.
    Without /NAME=, the name given to TCPIP.SYS is used, or, without
    one, PMDOS- and six digits from the network card's address.

{b}Related Commands{p}

Load the network card's driver on a [[DEVICE=]] line above this one.
NETBEUI.SYS and [[TCPIP.SYS]] can both be loaded, in either order.
#notes
{b}What NetBEUI is used for{p}

NET USE tries TCP/IP first.  When TCPIP.SYS is not loaded, or the
server cannot be found with it, NET USE connects with NetBEUI.  SMBSRV
answers on both.  NetBEUI does not cross routers: it reaches only the
computers on the same network.

{b}The name{p}

At start-up NETBEUI.SYS checks that no other computer is using the
name.  If one is, it says so and does not load.

{b}Network cards{p}

For now only NE2000.SYS can carry NetBEUI.  With another card driver,
NETBEUI.SYS says the card cannot be shared and does not load.
#examples
To use NetBEUI alone:

    device=c:\dos\ne2000.sys
    device=c:\dos\netbeui.sys /name=pmdos1

To use NetBEUI and TCP/IP, with one name for both:

    device=c:\dos\ne2000.sys
    device=c:\dos\tcpip.sys /name=pmdos1
    device=c:\dos\netbeui.sys
#topic PING|Ping
Sends echo requests to another computer, to see whether it answers.

{b}Syntax{p}

    PING [-n count] [-w timeout] host

{b}Parameters{p}

host
    A computer name or an IP address.

{b}Switches{p}

-n count
    How many requests to send.  Default is 4.

-w timeout
    How long to wait for each answer, in milliseconds.  Default is 1000.

{b}Related Commands{p}

To see this computer's own address, see [[IPCONFIG]].
#notes
{b}Names{p}

A name of up to 15 letters with no dot, such as SERVER, is looked up as
a Windows computer name first: the WINS server is asked if there is
one, then the other computers on the network.  Any other name, and a
short name nobody answers for, is looked up with DNS.

{b}Times{p}

Times are measured with the computer's clock tick, so they go up in
steps of 55 milliseconds.  "time<55ms" means the answer came within one
tick.

{b}The exit code{p}

0 when at least one request was answered, 1 when none was or the name
could not be found.
#examples
To see whether SERVER answers:

    PING SERVER

To send ten requests to an address:

    PING -n 10 192.168.1.1
#topic PMD|Pmd
Shows what is in the machine: the processor, memory, disks, video,
mouse, ports, interrupts and the kernel's own settings, a page at a
time.

{b}Syntax{p}

    PMD [/I]
    PMD /F [drive:][path]filename
    PMD /P [drive:][path]filename
    PMD /S [[drive:][path]filename]

PMD on its own shows a screen of buttons, one for each page.

{b}Switches{p}

/I
    Skips the look at the hardware before the first screen; each page
    is looked at when it is opened.

/F file
    Asks who the report is for, then writes the whole report to the
    file.

/P file
    Writes the whole report to the file without asking anything.

/S [file]
    Writes the summary to the file, or to the screen with no file.

{b}Related Commands{p}

For memory alone, see [[MEM]]; for the CD-ROM drives, see [[CDEX]];
for the Plug and Play cards, see [[ISAPNP]].
#notes
{b}The pages{p}

Computer, Memory, Video, Network, OS Version, Mouse, Other Adapters,
Disk Drives, LPT Ports, COM Ports, IRQ Status, TSR Programs and
Device Drivers, as MSD had them.  Press a page's letter or click its
button; the File, Utilities and Help menus are on the bar.

{b}Where the facts come from{p}

The kernel is asked, and its answers are what it is running with: the
memory it has, the drives it mounted, the interrupt lines it keeps.
#examples
To look round the machine:

    pmd

To write the full report to a file for someone else to read:

    pmd /p c:\report.txt
#topic QBASIC|Qbasic|QBasic
Starts QBasic, for writing and running programs in BASIC.

{b}Syntax{p}

    QBASIC [/B] [/EDITOR] [/G] [/H] [/MBF] [/NOHI]
           [[/RUN] [drive:][path]filename]

{b}Parameters{p}

[drive:][path]filename
    The program to load.  .BAS is assumed if no extension is given.

{b}Switches{p}

/EDITOR
    Starts the PM-DOS Editor instead of QBasic.  Same as EDIT.

/H
    Uses as many screen lines as the display allows: 43 or 50.

/MBF
    Makes MKS$, MKD$, CVS and CVD use Microsoft Binary Format, for
    programs written for older versions of BASIC.

/RUN
    Runs the program as soon as it is loaded.  A SYSTEM statement in
    the program returns to DOS.

/B, /G, /NOHI
    For backwards compatibility only.  Has no effect under PM-DOS.

{b}Related Commands{p}

For editing text files, see [[EDIT]].
#notes
{b}Requirements{p}

A math coprocessor is required: a 486DX, or a 386 with a 387.  The
help file, QBASIC.HLP, is looked for in the same directory as
QBASIC.EXE, in the PM-DOS directory, in the current directory and on
the PATH.  Setup puts both files in the PM-DOS directory.

{b}Programs written for MS-DOS{p}

Programs written for QBasic 1.1 run unchanged.  PM-DOS has no real
mode, so PEEK, POKE and DEF SEG only reach the program's own
variables, the screen and the BIOS data area, and CALL ABSOLUTE gives
"Advanced feature unavailable".  Arrays can be larger than 64K.

{b}Making an .EXE file{p}

Make EXE File on the Run menu writes the program as an .EXE file that
runs at the command prompt without QBasic.  QBasic builds the .EXE
file from QBRUN.EXE, which has to be in QBasic's directory or on the
PATH.  Setup puts QBRUN.EXE beside QBASIC.EXE.  The .EXE file does not
need QBRUN.EXE or QBasic to run, but it needs a math coprocessor.

With Produce Debug Code checked, Ctrl+Break stops the program, and an
error message gives the line number when the line has one.  In an
.EXE file, CHAIN and RUN with a file name start another .EXE file,
not a .BAS file.
#examples
To start QBasic:

    qbasic

To run a program and return to DOS when it executes SYSTEM:

    qbasic /run games\nibbles
#topic RAMDISK.SYS|Ramdisk.sys
Uses part of the computer's memory as a disk drive.

{b}Syntax{p}

    DEVICE=[drive:][path]RAMDISK.SYS [size [sector-size [entries]]] [/E | /A]
           [/L:x]

{b}Parameters{p}

[drive:][path]
    Location of the RAMDISK.SYS file.

size
    Size of the RAM disk in kilobytes, from 4 to 2,096,896.  Default
    is 64.  A larger size is reduced to 2,096,896.

sector-size
    128, 256, 512 or 1024.  For backwards compatibility only.  PM-DOS
    always uses 512-byte sectors.

entries
    How many files and directories the root directory can hold, from
    2 to 1024.  Default is 64.  The number is rounded up to a multiple
    of 16.

{b}Switches{p}

/E
    For backwards compatibility only.  Has no effect under PM-DOS.

/A
    For backwards compatibility only.  Has no effect under PM-DOS.

/L:x
    The drive letter to use.  If another drive already has the letter,
    the RAM disk gets the next free drive letter.

{b}Related Commands{p}

RAMDISK.SYS is loaded with [[DEVICE=]].  Each DEVICE= line makes one
more RAM disk.
#notes
{b}The drive letter{p}

The RAM disk gets the next free drive letter, or the letter /L:
names.  RAMDISK.SYS shows the letter and the size when CONFIG.SYS
runs.

{b}Memory{p}

The RAM disk is made from extended memory, which leaves that much less
for programs that use XMS.  It uses no conventional memory.

{b}Windows{p}

The RAM disk can still be used while Windows is running.

{b}Deleted files{p}

Files deleted from a RAM disk are kept for [[UNDELETE]] as they are on
any other disk, and they take up some of its space until they are
purged.

Everything on a RAM disk is lost when the computer is restarted or
turned off.  Copy what you want to keep to another disk first.
#examples
To make a 4 MB RAM disk:

    device=c:\dos\ramdisk.sys 4096

To make a 1 MB RAM disk whose root directory holds 128 files:

#topic SCANDISK|Scandisk|ScanDisk
Checks a disk for errors and repairs them, and can test the surface.

{b}Syntax{p}

    SCANDISK [drive: [drive: ...] | /ALL]
             [/CHECKONLY | /AUTOFIX [/NOSAVE] | /CUSTOM]
             [/SURFACE] [/G] [/NOSUMMARY]
    SCANDISK /FRAGMENT [drive:][path]filename
    SCANDISK /UNDO [undo-drive:] [/G]

SCANDISK on its own checks the current drive, asking about each
problem it finds.

{b}Parameters{p}

drive:
    The drive to check.  Several can be named.

{b}Switches{p}

/ALL
    Checks every hard disk.

/CHECKONLY
    Looks for errors and repairs nothing.

/AUTOFIX
    Repairs errors without asking.  Lost clusters are saved as files
    in the root directory.

/NOSAVE
    With /AUTOFIX: frees lost clusters instead of saving them.

/CUSTOM
    Runs as the [CUSTOM] section of SCANDISK.INI says.

/SURFACE
    Scans the surface of the disk after the other checks, without
    asking first.

/G
    Uses a graphics screen.

/NOSUMMARY
    Shows no summary after each drive, and does not ask for an Undo
    disk.

/FRAGMENT
    Reports which of the files named are in more than one piece.

/UNDO
    Undoes the repairs ScanDisk last made, from the Undo disk in
    undo-drive.  A: if none is given.

{b}Related Commands{p}

For the report alone, see [[CHKDSK]].  To put the files into one piece
afterwards, see [[DEFRAG]].  [[AUTOCHECK=]] in CONFIG.SYS checks a disk
at startup when it was not shut down properly.
#notes
{b}exFAT{p}

ScanDisk checks FAT12, FAT16 and FAT32 drives.  exFAT drives are not
supported.

{b}What it checks{p}

The media descriptor, the file allocation tables, the directory
structure and the file system, in that order, and then the surface
if asked.  Long file names are checked with the rest.

{b}The Undo disk{p}

Before repairing, ScanDisk offers to write what it changes onto a
diskette, so that SCANDISK /UNDO can put the disk back as it was.

{b}SCANDISK.INI{p}

The settings - whether to ask, what to do with lost clusters, whether
to scan the surface - are read from SCANDISK.INI where the system's
files are.  The [CUSTOM] section is what /CUSTOM runs.  The settings
about DoubleSpace and DriveSpace are read and ignored: PM-DOS has no
compressed drives.

{b}The exit code{p}

    0    no problems found
    1    the command line was wrong, or a drive cannot be checked
    2    out of memory
    3    left before the checks had finished
    4    every check finished, but a surface scan was left early
  254    problems found, and all of them repaired
  255    problems found, and not all of them repaired
#examples
To check drive C and be asked about each problem:

    scandisk c:

To check every hard disk and repair without asking, from a batch
file:

    scandisk /all /autofix /nosummary

To test the surface of a diskette:

    scandisk a: /surface

To find out whether a file is in one piece:

    scandisk /fragment c:\data\*.dbf
#topic SETUP|Setup
Installs PM-DOS on the hard disk, or makes a startup floppy.

{b}Syntax{p}

    SETUP [/F] [/G]

{b}Switches{p}

/F
    Makes a floppy disk that starts the computer and runs PM-DOS,
    instead of installing on the hard disk.  F7 on Setup's first
    screen does the same.

/G
    Does not make an Uninstall disk when Setup replaces another DOS.

{b}Related Commands{p}

To divide a hard disk yourself before installing, use [[FDISK]].
#notes
{b}Where to run Setup{p}

Setup reads the files it installs from wherever SETUP.EXE is: a Setup
disk, the CD, a USB stick or a network directory.  Run under MS-DOS,
Setup replaces that DOS with PM-DOS.  Started by restarting the
computer from Setup Disk 1, the CD or a USB stick, Setup can also
prepare and format a new hard disk.

{b}A new hard disk{p}

When the first hard disk has no partitions, Setup makes one partition
of the free space and restarts the computer.  Setup then starts again
by itself and formats the drive.  Disks of 512MB and more are
formatted FAT32.  To divide the disk another way, leave Setup, run
FDISK, and restart from the Setup disk.

The old DOS commands that PM-DOS replaces are moved to C:\OLD_DOS.1,

are made REM lines.  To put the old DOS back, start the computer from
the Uninstall disk Setup made and press ENTER.

PMIO.SYS, PMDOS.SYS and RMDOS.SYS go in the root of drive C:,
everything else in C:\DOS or the directory you choose.  CONFIG.SYS

To install PM-DOS from the diskette in drive A:

    a:setup

    setup /f

#topic SETVER|Setver
Sets the DOS version number reported to a program.

{b}Syntax{p}

    SETVER [drive:path]
    SETVER [drive:path] filename n.nn
    SETVER [drive:path] filename /DELETE [/QUIET]

{b}Parameters{p}

[drive:path]
    Location of the SETVER.EXE file to list or change.  Defaults to
    the SETVER.EXE that was run.

filename
    The program's file name and extension, without a path.  For
    example, EDLIN.EXE.  Use * for every program that is not in the
    table.

n.nn
    The version number to report to the program, from 2.11 to 9.99.

/DELETE or /D
    Removes the program's entry from the table.

/QUIET or /Q
    Used with /DELETE.  No message is shown when the entry is removed.

{b}Related Commands{p}

The version table is used only when CONFIG.SYS loads it with
[[DEVICE=]].
#notes
{b}Why SETVER is needed{p}

PM-DOS reports its own version number, the one VER shows.  Most DOS
programs read a version below 2 as MS-DOS 1 and will not run.  Some
older programs and drivers refuse to run on any version other than
the one they were written for.  SETVER's table lists those programs
and the version number each one is given.  The * entry is the
version given to every other DOS program.  As supplied it is 6.22.

{b}Loading the table{p}

Add DEVICE=C:\SETVER.EXE to CONFIG.SYS to load the table.  Put the
line above any driver listed in the table.  The table uses less than
1K of memory.  The CONFIG.SYS that Setup writes already has this
line.  Without it, DOS programs are told PM-DOS's own version.

{b}Changes{p}

SETVER changes the table in the SETVER.EXE file, not the copy in
memory.  Changes take effect the next time the computer starts.  A
changed entry moves to the end of the table.

{b}What is reported{p}

Programs listed in the table, and all others when there is a *
entry, get their version number from INT 21h function 30h, in DOS
sessions and under Windows.  Function 3306h always reports PM-DOS's
own version.  PM-DOS's own 32-bit programs are not affected.

{b}Errorlevels{p}

    0    Success
    1    Invalid switch
    2    Invalid file name
    4    Invalid version number
    5    The program is not in the table
    6    SETVER.EXE not found
    7    Invalid drive
    8    Too many parameters
    9    No version number or switch after the file name
   10    SETVER.EXE could not be read
   11    The version table is damaged
   12    The file is not a SETVER.EXE file
   13    The version table is full
   14    SETVER.EXE could not be written
   15    The path is too long
#examples
    setver
    setver edlin.exe 5.00
    setver * 6.22
    setver edlin.exe /delete
    setver c:\old netx.exe 5.00

Puts the PM-DOS system files on a disk, making it bootable.

#topic TCPIP.SYS|Tcpip.sys
Loads the TCP/IP network protocol, which the network commands and
NET USE use.

{b}Syntax{p}

    DEVICE=[drive:][path]TCPIP.SYS [/IP=address [/MASK=mask] [/GW=address]]
           [/DNS=address] [/WINS=address] [/NAME=name]

{b}Parameters{p}

[drive:][path]
    Location of the TCPIP.SYS file.

{b}Switches{p}

/IP=address
    A fixed IP address, such as 192.168.1.20.  Without /IP=, the address
    comes from a DHCP server.

/MASK=mask
    The subnet mask, such as 255.255.255.0.  Used only with /IP=.
    Defaults to 255.0.0.0 for an address starting 1 to 127, 255.255.0.0
    for 128 to 191, and 255.255.255.0 for the rest.

/GW=address
    The default gateway: the router to other networks.  Used only with
    /IP=, and must be on the same network as the address.

/DNS=address
    The DNS server that looks up names.  With DHCP, this server is used
    in place of the one the DHCP server names.

/WINS=address
    The WINS server that looks up Windows computer names.  With DHCP,
    this server is used in place of the one the DHCP server names.

/NAME=name
    This computer's name on a Windows network, up to 15 letters and
    digits.  Other computers can then find it by the name, as
    \\name.  Without /NAME=, the computer has no name of its own.

{b}Related Commands{p}

Load the network card's driver on a [[DEVICE=]] line above this one.  To
see the address, see [[IPCONFIG]].  To see whether another computer
answers, see [[PING]].
#notes
{b}Getting an address{p}

Without /IP=, TCPIP.SYS asks a DHCP server for an address and waits up
to five seconds for the answer.  It then shows "IP Address:" and the
address, or "Failed to get IP address".  After a failure it keeps
asking in the background, so the network can still come up a little
later.

The address is lent for a time, called the lease.  TCPIP.SYS renews
the lease when half of it has passed, and drops the address if the
lease runs out.

{b}Computer names{p}

A name of up to 15 letters with no dot, such as \\SERVER in NET USE,
is looked up as a Windows computer name first: the WINS server is
asked if there is one, then the other computers on the network.  DNS
is asked last, and for every other name.

{b}Mistakes on the line{p}

An address or mask that is not valid stops TCPIP.SYS from loading, and
the reason is shown.  A switch TCPIP.SYS does not know is shown and
skipped.
#examples
To get the address from a DHCP server:

    device=c:\dos\ne2000.sys
    device=c:\dos\tcpip.sys

To use a fixed address:

    device=c:\dos\ne2000.sys
    device=c:\dos\tcpip.sys /ip=192.168.1.20 /gw=192.168.1.1

To give the computer the name PMDOS1 on a Windows network:

    device=c:\dos\tcpip.sys /name=pmdos1

#topic UNDELETE|Undelete
Restores deleted files.

{b}Syntax{p}

    UNDELETE [drive:][path][name] [/LIST | /ALL] [/S]
    UNDELETE [drive:] /PURGE
    UNDELETE [drive:] /STATUS

UNDELETE on its own lists the files deleted from the current
directory and asks about each one.

{b}Parameters{p}

[drive:][path]
    The directory the files were deleted from.  The current one if
    none is given.

name
    Name of file to be restored.  Wildcards accepted.

{b}Switches{p}

/LIST
    Lists the files and recovers nothing.

/ALL
    Recovers all files without asking.

/S
    Includes sub-directories as well.

/PURGE
    Deletes every kept file on the drive for good.

/STATUS
    Shows what is being kept and how much room it takes.

{b}Related Commands{p}

[[UNDELETE=]] in CONFIG.SYS turns delete protection off.  See [[DEL]]
for what is never kept.
#notes
{b}How it works{p}

With UNDELETE=ON, which is the setting unless changed, the kernel
does not free a deleted file: it moves it into a hidden RECYCLED
directory on the same drive and notes where it came from.  UNDELETE
reads those notes, and recovering a file is moving it back.

{b}Nothing is written over{p}

A file whose name has been used again since comes back with # in
place of its first letter.  A directory that has gone is made again.

{b}What is kept{p}

Up to a tenth of the drive's free space.  When more room is needed
the oldest kept files go first.  Files bigger than that, *.TMP and
*.$$$ files, and anything deleted inside RECYCLED are gone at once.
Protection does not work while Windows is running.
#examples
To see what can be brought back from the current directory:

    undelete /list

To bring back every deleted .DOC file in \LETTERS:

    undelete \letters\*.doc /all

To free the space the kept files take on drive C:

    undelete c: /purge
#topic USB|Usb
Lists the USB controllers, the devices plugged into them, and the USB
disk units with their drive letters.

{b}Syntax{p}

    USB

{b}Related Commands{p}

[[USB=]] in CONFIG.SYS turns PM-DOS's USB support off and on and says
how many drive letters are kept for USB disks.  [[FDISK]] and
[[FORMAT]] work on a USB disk as on any other.
#notes
{b}What the lines say{p}

Each controller: its kind (UHCI or OHCI), its address, how many ports
it has, and whether it was taken from the BIOS.  Each device: where it
is (controller:port, or the hub and port behind that), what it is
(keyboard, mouse, disk, hub), its speed, and the name it gives itself.
Each disk unit: its drive letter, the make and model, and the size.

{b}Plugging and unplugging{p}

A USB disk's letter is there from boot, like A:, whether or not a disk
is plugged in.  Plug one in and the letter answers; pull it out and the
letter says "Not ready" until the next one comes.  Nothing is printed
when a device is plugged in or removed: this command is how to see what
the kernel found.

A disk that was plugged in before the machine started, and that the
BIOS showed as a hard disk, keeps the letter the boot gave it (D:, say)
and is listed under that letter here.  Its USB letter stays empty.  A
blank disk has no such letter, so the USB letter takes it and FORMAT
works on that.

Pull a disk out only when nothing is being written to it.  As with a
diskette, what a program has written is on the disk once the program
has finished or the prompt has come back.

{b}Keyboards and mice{p}

A USB keyboard and a USB mouse work from the moment the kernel has
taken the controllers, which is just after CONFIG.SYS.  Until then the
BIOS drives them, as it did before PM-DOS started.
#examples
    usb
#topic XARC|Xarc|XArchive
Lists, tests and extracts archives, and makes zip and 7z archives, on
a screen of its own or from the command line.

{b}Syntax{p}

    XARC [[drive:][path]archive] [/G | /T]
    XARC L archive [/Ppassword]
    XARC T archive [/Ppassword]
    XARC X archive [directory] [/Ppassword] [/NOPATHS]
    XARC A archive name [name...] [/R] [/Xnames] [/NOPATHS] [/Y] [/AC]

{b}Parameters{p}

archive
    The archive.  On its own it is opened on XARC's screen.  With no
    archive at all, the screen starts in the current directory.

L
    Lists what the archive holds.

T
    Tests the archive: every file in it is unpacked and checked, and
    nothing is written.

X
    Extracts the whole archive into directory, or into the current
    directory.

A
    Makes a new archive of the files and directories named.  .7Z makes
    a 7-Zip archive, anything else a zip, and a name with no extension

MEM
    Shows how much memory XARC can have, which decides how big an
    archive it can extract.

{b}Switches{p}

/G
    Uses the VGA graphics screen this time.

/T
    Uses the text screen this time.

/Ppassword
    The password for an encrypted archive.  Anyone who sees the command
    can read it.

/NOPATHS
    With X, puts every file in the one directory.  With A, stores the
    files without their directory names.

/R
    With A, finds files that match a name like *.TXT in subdirectories
    too.

/Xnames
    With A, leaves out files that match names, separated by semicolons.
    /X@file reads the names from a file, one to a line.

/Y
    With A, replaces an archive of the same name without asking.

/AC
    With A, clears the Archive attribute of each file stored.

To copy directories without packing them, see [[XCOPY]].

{b}The screen{p}

An archive is listed like a directory.  ENTER opens a folder, or an

file, F5 extracts what is marked, F3 shows a text file and F7 tests the
archive.  Go back past the top of the archive and the disk is listed:
mark files there and F8 packs them.  F1 lists every key, and the mouse
works the menus, the list and the scroll bar.

Zip, 7z, RAR from 2.0 to 5 (multi-volume sets too), cabinet (.CAB)

password.

{b}Long file names{p}

Names keep their long form on a drive that has long names.  On a drive
without them, or with LFN=OFF, each name is shortened the way Windows
95 does it: LONGFI~1.TXT, LONGFI~2.TXT.

{b}Settings{p}

The Options menu's choices are kept in XARCHIVE.INI, beside XARC.EXE.

{b}Memory{p}

A 7z or RAR archive packed with a large dictionary needs that much
memory in one piece to extract.  XARC MEM shows what this machine can
give, and Archive Info (F4) shows what an archive needs.

To look through an archive:

    xarc drivers.zip

To extract one into a new directory:

    xarc x drivers.zip c:\drivers

    xarc a c:\backup\work.7z c:\work

    the destination to be a directory without asking.

/Q
    Does not show the names as it copies.

/F
    Shows the full source and destination name of each copy.

/L
    Lists the files that would be copied, and copies nothing.

/H
    Copies hidden and system files too.

/R
    Writes over read-only files.

/T
    Makes the directory structure and copies no files.  With /E, the
    empty directories too.

/U
    Copies only files that already exist at the destination.

/K
    Keeps the attributes.  Without it, read-only is cleared on the
    copies.

/N
    Copies using the short names.

/Y
    Replaces files at the destination without asking.

/-Y
    Asks before replacing.

{b}Related Commands{p}

For a file or two, see [[COPY]].  To move rather than copy, see
[[MOVE]].  To set the archive attribute /A and /M look at, see
[[ATTRIB]].
#notes
{b}File or directory?{p}

When the destination does not exist and more than one file is being
copied, XCOPY asks whether it is a file or a directory.  A backslash
on the end of the name, or /I, makes it a directory without asking.

{b}Long names{p}

Names are copied as they are on the disk, long ones included.  /N
copies under the short names, for a disk that cannot hold long ones.

{b}COPYCMD{p}

SET COPYCMD=/Y stops the asking before files are replaced, for XCOPY
as for COPY and MOVE.

{b}The exit code{p}

0 indicates success; all files were copied, 1 nothing was found to
copy, 2 stopped with Ctrl+C, 4 could not start or out of space, 5 a
file could not be read or written.
#examples
To copy a directory and everything under it to another drive:

    xcopy c:\work d:\work /s /e

To copy only the files changed since a backup, clearing the mark:

    xcopy c:\work a: /m /s

To copy the files changed on or after a date:

    xcopy *.doc d:\recent /d:03-01-2026

To see what would be copied without copying it:

    xcopy c:\work d:\work /s /l
