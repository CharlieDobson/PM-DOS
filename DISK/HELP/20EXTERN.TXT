#topic ACROREAD|Acroread
Shows a PDF document on the screen, a page at a time, as a picture or
as its text.

{b}Syntax{p}

    ACROREAD [drive:][path]filename [/T | /G] [/P:n] [/X]

{b}Parameters{p}

[drive:][path]filename
    The document.  .PDF is added to a name that has no extension.

{b}Switches{p}

/T
    Starts with the text of the page, on the text screen, instead of
    the page drawn.

/G
    Draws the pages in sixteen greys on the standard VGA screen,
    without asking the video BIOS for a better mode.

/P:n
    Starts at page n.

/X
    Writes the document's text to standard output, a form feed between
    pages, and does not show a screen at all.

{b}Related Commands{p}

To read a plain text file, see [[EDIT]] or [[TYPE]].
#notes
{b}The screens{p}

A page is drawn 640 by 480: in colour when the video BIOS has VBE 2.0
or later, in sixteen greys on a plain VGA.  The menu bar has File,
View, Page, Search and Help; F1 lists the keys.  PAGE DOWN and PAGE UP
turn the pages, the arrow keys move around a page, and the mouse drags
it or works the scroll bars.

{b}What it reads{p}

Any PDF from version 1.0 to 2.0, including files saved many times
over, files with damaged cross-reference tables, and files encrypted
with the standard handler.  Pictures and fonts are drawn as far as
the program knows how; what it leaves out is left blank.
#examples
To read a manual:

    acroread manual.pdf

To start at page 12 with the text view:

    acroread manual /t /p:12

To print the words of a document:

    acroread manual /x > prn
#topic ANSI.SYS|Ansi.sys
Lets programs move the cursor, clear the screen, change colours and
give keys new meanings, by writing escape sequences to the screen.

{b}Syntax{p}

    DEVICE=[drive:][path]ANSI.SYS [/X] [/K] [/R]

{b}Parameters{p}

[drive:][path]
    Location of the ANSI.SYS file.

{b}Switches{p}

/X
    Lets the grey keys of a 101-key keyboard be given meanings of
    their own, apart from the same keys on the numeric keypad.

/K
    Treats a 101-key keyboard as an 84-key keyboard.  Use it with
    programs that do not recognise the extra keys.

/R
    Sends all screen output through the video BIOS.  Use it with
    screen reader programs.

{b}Related Commands{p}

ANSI.SYS is loaded with [[DEVICE=]].  [[PROMPT]] can send escape
sequences with $E.
#notes
{b}Escape sequences{p}

Each sequence starts with ESC, character 27, followed by a left
bracket.  Numbers in a sequence are separated by semicolons.  A number
left out of a cursor movement counts as 1.

    ESC[r;cH    Moves the cursor to row r, column c.  The top left
                corner is 1;1.  ESC[r;cf does the same.
    ESC[nA      Moves the cursor up n rows.
    ESC[nB      Moves the cursor down n rows.
    ESC[nC      Moves the cursor right n columns.
    ESC[nD      Moves the cursor left n columns.
    ESC[s       Saves the cursor position.
    ESC[u       Moves the cursor back to the saved position.
    ESC[6n      Reports the cursor position as typed input: ESC[r;cR
                followed by ENTER.
    ESC[2J      Clears the screen and moves the cursor to the top left
                corner.
    ESC[K       Clears from the cursor to the end of the line.
    ESC[n;...m  Sets the colours.  See below.
    ESC[=nh     Sets screen mode n.  See below.
    ESC[=7h     Text wraps at the end of a line.  This is the default
                setting.
    ESC[=7l     Text stops at the end of a line.
    ESC[k;...p  Gives key k a new meaning.  See below.

{b}Colours{p}

    0  Normal        30  Black text      40  Black background
    1  Bright        31  Red text        41  Red background
    4  Underline     32  Green text      42  Green background
    5  Blinking      33  Yellow text     43  Yellow background
    7  Reverse       34  Blue text       44  Blue background
    8  Hidden        35  Magenta text    45  Magenta background
                     36  Cyan text       46  Cyan background
                     37  White text      47  White background

On a colour screen underline shows as blue text.

{b}Screen modes{p}

    0   40x25 black and white      13  320x200, 16 colours
    1   40x25 colour               14  640x200, 16 colours
    2   80x25 black and white      15  640x350 black and white
    3   80x25 colour               16  640x350, 16 colours
    4   320x200, 4 colours         17  640x480, 2 colours
    5   320x200 black and white    18  640x480, 16 colours
    6   640x200 black and white    19  320x200, 256 colours

{b}New meanings for keys{p}

In ESC[k;...p, k is the key's character code.  A key with no character
code is 0 and its scan code: 0;59 is F1.  The rest of the sequence is
what the key types instead, as character codes or as text in quotes.
ESC[kp on its own gives the key back its own meaning.  With /X, a grey
key is 224 and its scan code.

Programs that read the keyboard directly, such as EDIT, are not
affected by new key meanings.  In DOS windows under Windows, escape
sequences work but new key meanings do not.
#examples
To show the drive and directory in yellow on blue:

    prompt $e[1;33;44m$p$g$e[0;37;44m

To make F10 type DIR and press ENTER, set again each time the prompt
is shown:

    prompt $e[0;68;"DIR";13p$p$g
#topic ATTRIB|Attrib
Shows or changes the attributes of files: read-only, archive, system
and hidden.

{b}Syntax{p}

    ATTRIB [+R | -R] [+A | -A] [+S | -S] [+H | -H]
           [[drive:][path][filename]] [/S]

Type ATTRIB on its own to see the attributes of every file in the
current directory.

{b}Parameters{p}

+
    Sets the attribute that follows.

-
    Clears it.

R
    Read-only: the file cannot be changed or deleted.

A
    Archive: the file has changed since it was last backed up.  Every
    file written gets it; XCOPY /M clears it.

S
    System.

H
    Hidden: DIR leaves the file out unless /A asks for it.

[drive:][path][filename]
    The file or files to show or change.  Wildcards name several.

{b}Switches{p}

/S
    Works on the files named in the directory and in every directory
    below it.

{b}Related Commands{p}

To copy files by their archive attribute, see [[XCOPY]].
#notes
{b}What it shows{p}

One line a file: the attribute letters in columns, then the path and
name.  A directory named on the command line is shown with its own
attributes, not opened.

{b}The other bits{p}

The directory and volume-label attributes belong to the file system
and cannot be set or cleared here.

{b}A hidden or system file{p}

Clearing R, S and H together is how a system file is made ordinary
again.  PM-DOS's own PMIO.SYS, PMDOS.SYS and RMDOS.SYS are marked
read-only, hidden and system, and SYS puts the marks back.
#examples
To see the attributes of every file here:

    attrib

To make a file read-only:

    attrib +r report.doc

To take the hidden and system attributes off a file:

    attrib -h -s secret.dat

To mark every .TXT file below the current directory as needing a
backup:

    attrib +a *.txt /s
#topic CACHE|Cache
Shows what the disk cache built into PM-DOS is doing, and controls it.

{b}Syntax{p}

    CACHE [/X] [drive[+ | -] ...] [/C | /R] [/Q | /S]

Type CACHE on its own for the report: each drive and how it is cached,
and the cache's size.

{b}Parameters{p}

drive
    A drive letter on its own: that drive is read-cached only, with
    write-behind turned off.

drive+
    Write-behind turned on for that drive.

drive-
    That drive not cached at all.

{b}Switches{p}

/X
    Turns write-behind off for every drive.

/C
    Writes everything the cache is holding to the disks.

/R
    Writes everything out, then empties the cache and starts it again.

/Q
    Says nothing.

/S
    Adds the hit and miss counts and the number of elements to the
    report.

{b}Related Commands{p}

The cache's size is set by [[CACHE=]] in CONFIG.SYS, and the one
Windows uses by [[WINCACHE=]].  [[SHUTDOWN]] writes everything out
before switching off.
#notes
{b}What is cached{p}

Hard disks are read- and write-cached.  Floppies, CD-ROMs and drives
from loaded block drivers are read-cached only, and that has no
switch.

{b}Write-behind{p}

With write-behind on, a file's sectors are written when the program
ends or the cache has to make room, and always before the prompt
comes back, so switching off at the prompt is safe.  CACHE /C writes
them out at once.  VERIFY ON writes straight through.

{b}The three sizes{p}

The report shows what the cache holds now, the least it will shrink
to when a program needs memory, and the most it may grow to.  All
three come from CACHE= in CONFIG.SYS.
#examples
To see the report with the hit counts:

    cache /s

To write everything out before a program that reads the disk its own
way:

    cache /c

To stop caching drive A: and keep write-behind on for C:

    cache a- c+
#topic CDEX|Cdex
Lists the CD-ROM drives and their drive letters.

{b}Syntax{p}

    CDEX

{b}Related Commands{p}

[[CDROM=]] in CONFIG.SYS chooses the first letter; [[SCSI=]] turns the
SCSI drivers on and off.  To give an .ISO file a drive letter, see
[[MOUNT]].
#notes
{b}What the lines say{p}

One line a drive: its letter, the unit number that MSCDEX-style
programs count it by, where it is (an IDE channel or a SCSI ID), the
label of the disc in it, and the name the drive reports.  With a
drive on a SCSI card, the cards are listed under the table; "SCSI 1
ID 2" is ID 2 on the first card.

{b}No MSCDEX{p}

The CD-ROM extensions are part of the kernel, and a drive has its
letter from boot.  There is nothing to load.
#examples
    cdex
#topic CHKDSK|Chkdsk
Checks a disk and reports on it.  With /F, it repairs what it finds.

{b}Syntax{p}

    CHKDSK [drive:][[path]filename] [/F] [/V]

Type CHKDSK on its own to check the current drive.

{b}Parameters{p}

[drive:][path]
    The drive to check.

filename
    A file, or files named with wildcards, to report on: CHKDSK says
    whether each one is stored in one piece.

{b}Switches{p}

/F
    Fixes errors.  Without it, CHKDSK reports them and changes nothing.

/V
    Lists the path and name of every file on the disk as it goes.

{b}Related Commands{p}

For a check that asks about each problem, keeps an undo disk and can
scan the surface, see [[SCANDISK]].  [[AUTOCHECK=]] in CONFIG.SYS runs
CHKDSK at startup on a disk that was not shut down properly.
#notes
{b}exFAT{p}

CHKDSK checks FAT12, FAT16 and FAT32 drives.  exFAT drives are not
supported.

{b}What it checks{p}

The file allocation tables, the directories, and every file's chain
of clusters: clusters that belong to no file, and clusters two files
claim.  Then it reports the disk's size and how much of it each kind
of thing takes.

{b}Lost clusters{p}

With /F, clusters that belong to no file are saved as FILE0000.CHK
and so on in the root directory, where they can be looked at and
deleted.

{b}When it runs{p}

Nothing else should be writing to the disk while CHKDSK /F runs.
CHKDSK cannot check a network drive.

{b}The exit code{p}

255 when a problem was found, 0 otherwise.
#examples
To check drive C and fix what is wrong:

    chkdsk c: /f

To find out whether a file is in one piece:

    chkdsk c:\data\big.dat
#topic CHOICE|Choice
Asks a question in a batch file and sets the errorlevel to the answer.

{b}Syntax{p}

    CHOICE [/C[:]keys] [/N] [/S] [/T[:]c,nn] [text]

{b}Parameters{p}

text
    The question.  CHOICE shows it, then the keys in brackets and a
    question mark.

{b}Switches{p}

/C[:]keys
    The keys that count as answers.  Y and N if not given.

/N
    Shows the question without the keys and the question mark.

/S
    Capitals and small letters are different answers.

/T[:]c,nn
    Takes c as the answer after nn seconds with no key pressed.

{b}Related Commands{p}

To act on the errorlevel, see [[IF]].  For the other commands written
for batch files, see [[Batch Commands|Batch]].
#notes
{b}The errorlevel{p}

The first key in the list sets errorlevel 1, the second 2, and so on.
Test the highest number first, because IF ERRORLEVEL means "that or
more".

{b}Wrong keys{p}

A key that is not in the list makes a beep and CHOICE waits again.
#examples
To ask yes or no:

    choice Delete the old files
    if errorlevel 2 goto no
    if errorlevel 1 goto yes

To offer three choices and take the first after ten seconds:

    choice /c:abc /t:a,10 Which backup
#topic DEBUG|Debug
Shows and changes memory, files and disk sectors, unassembles and
assembles instructions, and runs a PM-DOS program one instruction at a
time.

{b}Syntax{p}

    DEBUG [[drive:][path]filename [parameters]]

DEBUG's prompt is a hyphen.  Each command is a letter followed by its
parameters.  Type ? for a list of the commands.

{b}Parameters{p}

[drive:][path]filename
    The file to load.

parameters
    The command line for the program.

{b}Commands{p}

    A [address]                        Assemble
    C range address                    Compare
    D [range]                          Dump
    E address [list]                   Enter
    F range list                       Fill
    G [=address] [address...]          Go
    H value value                      Hex add and subtract
    I port                             Read a port
    L [address [drive sector count]]   Load
    M range address                    Move
    N [pathname] [arglist]             Name
    O port byte                        Write to a port
    P [=address] [count]               Proceed
    Q                                  Quit
    R [register]                       Register
    S range list                       Search
    T [=address] [count]               Trace
    U [range]                          Unassemble
    W [address [drive sector count]]   Write
    XA, XD, XM, XS                     Expanded memory

Numbers are in hexadecimal.  An address is [segment:]offset.  A range
is an address followed by an end offset, or by L and a length.  A list
is bytes, or text in quotation marks.
#notes
{b}PM-DOS programs and DOS programs{p}

G, T and P run PM-DOS programs.  A DOS program (.COM or .EXE) can be
loaded, dumped, unassembled, changed and written back, but not run.
G, T and P on a DOS program report that only a PM-DOS program can be
run.

{b}32-bit programs{p}

With a PM-DOS program loaded, R shows the 32-bit registers and offsets
have eight digits.  U shows 386 and 387 instructions, and A takes the
8086 and 8087 instructions with 32-bit registers and addresses.

{b}What DEBUG can change{p}

A DOS program is loaded into DEBUG's own part of conventional memory.
The rest of the first megabyte, such as the interrupt vectors and DOS
itself, can be read but not changed: E, F, M, A and L report df Error
there.  A PM-DOS program's own memory can be read and changed.

{b}Disk sectors{p}

L and W with a drive, a sector and a count read and write sectors
directly.  Drive 0 is A:, 1 is B:, 2 is C: and so on.  W does not ask
before writing over the sectors.

{b}Writing a file{p}

W writes the number of bytes in BX:CX, starting at CS:100, to the file
named with N.  .EXE and .HEX files cannot be written.  If the disk
fills up, the new file is deleted.

{b}Expanded memory{p}

XA, XD, XM and XS always report that there is no expanded memory.

{b}.HEX files{p}

A .HEX file is loaded as it is.  The records are not converted the way
MS-DOS's DEBUG converted them.

{b}Commands from a file{p}

DEBUG < file takes its commands from the file, and ends at the end of
the file even without a Q.

{b}Stopping{p}

CTRL+C ends the command DEBUG is carrying out and goes back to the
prompt.  CTRL+BREAK stops a PM-DOS program that DEBUG is running and
shows its registers.

{b}The exit code{p}

0, or 1 when there is not enough memory for DEBUG to start.
#examples
To see the first instructions of a program:

    debug myprog.com
    -u

To change a byte in a program and save it:

    debug myprog.com
    -e 105 90
    -w
    -q

To step through a PM-DOS program, then run it to the end:

    debug hello.exe
    -t
    -p
    -g

To read the boot sector of drive A: and look at it:

    debug
    -l 100 0 0 1
    -d 100 l 200
#topic DEFRAG|Defrag
Puts every file on a disk into one piece and moves the files to the
start of the disk, so they read faster and the free space is in one
block.

{b}Syntax{p}

    DEFRAG [drive:] [/F] [/S[:]order] [/H] [/B] [/G]
    DEFRAG [drive:] [/U] [/H] [/B] [/G]

With no switches, DEFRAG looks at the drive, recommends a method, and
asks.

{b}Parameters{p}

drive:
    The drive to optimize.

{b}Switches{p}

/F
    Full optimization: every file in one piece, and no free space
    between files.

/U
    Unfragments the files only.  Free space may be left between them.

/S[:]order
    Sorts the files in each directory, by one of:

    N    name                     E    extension
    D    date and time            S    size

    A minus sign after the letter reverses the order: /SN-.

/H
    Moves hidden files too.  System files are never moved.

/B
    Restarts the computer when DEFRAG has finished.

/G
    Uses a graphics screen.

{b}Related Commands{p}

DEFRAG checks the drive first and offers [[SCANDISK]] when it finds
errors.  [[CHKDSK]] reports whether a file is in one piece.
#notes
{b}exFAT{p}

DEFRAG works on FAT12, FAT16 and FAT32 drives.  exFAT drives are not
supported.

{b}The screen{p}

A map of the disk, a block for each group of clusters, shows the
files being moved.  The Optimize menu starts, stops and sets the
method; the mouse works the menus and the buttons.

{b}Safe to interrupt{p}

Files are moved in an order that leaves the disk whole at every step,
so a power cut in the middle loses nothing.  Run DEFRAG again to
finish.

{b}What is not moved{p}

System files, and hidden files unless /H is given.  Windows' swap
file is left where it is.

{b}The exit code{p}

    0    the drive was optimized
    2    no free cluster to work with
    3    stopped at the keyboard
    4    the command line was wrong, or the drive cannot be used
    5    a cluster could not be read
    6    a cluster could not be written
    7    the file system has errors: run ScanDisk
    9    not enough memory

/SKIPHIGH, /LCD, /BW and /G0 are MS-DOS's switches: they are accepted
and do nothing.
#examples
To optimize drive C fully, with the files in each directory in order
of name:

    defrag c: /f /sn

To unfragment the files on D: without moving them together:

    defrag d: /u
#topic DELTREE|Deltree
Deletes a directory along with all of its files and subdirectories.

{b}Syntax{p}

    DELTREE [/Y] [drive:]path [[drive:]path[...]]

{b}Parameters{p}

[drive:]path
    The directory or file to delete.  Wildcards are allowed, and they
    match directories as well as files.

{b}Switches{p}

/Y
    Deletes without asking first.

{b}Related Commands{p}

To remove an empty directory, see [[RD]].  To delete files only, see
[[DEL]].  To get deleted files back, see [[UNDELETE]].
#notes
{b}Asking first{p}

Without /Y, DELTREE asks about each directory or file it finds.  Type
Y or N, then press Enter.  Ctrl+C stops DELTREE.

{b}Everything goes{p}

Hidden, system and read-only files are deleted along with the rest.

{b}The directory or what is in it{p}

DELTREE \TEMP deletes TEMP itself.  DELTREE \TEMP\*.* deletes
everything in TEMP and keeps the directory.

{b}Getting it back{p}

With UNDELETE=ON, which is the default setting, deleted files are kept
the same as the ones DEL deletes.  UNDELETE /S brings back a whole tree
and makes the directories again.

{b}What is left{p}

A file that cannot be deleted is named, and so is the current
directory, which is never removed.  The directories holding them stay,
with everything else in them gone.

{b}The exit code{p}

    0    everything was deleted, or nothing matched
    1    the command line was wrong, or something could not be deleted
#examples
To delete \TEMP and everything in it without being asked:

    deltree /y \temp

To empty \TEMP but keep the directory:

    deltree \temp\*.*

To bring back a tree deleted from \OLD:

    undelete \old\*.* /s /all
#topic DISKCOMP|Diskcomp
Compares two diskettes track for track.

{b}Syntax{p}

    DISKCOMP [drive1: [drive2:]] [/1] [/8]

{b}Parameters{p}

drive1:
    The drive with the first diskette.

drive2:
    The drive with the second.  The same drive as the first, or left
    out, means one drive: the first diskette is read whole, and then
    DISKCOMP asks for the second.

{b}Switches{p}

/1
    Compares the first side only.

/8
    Compares only the first eight sectors of each track.

{b}Related Commands{p}

To make the copy DISKCOMP checks, see [[DISKCOPY]].  To compare files
rather than diskettes, see [[FC]].
#notes
{b}What counts as the same{p}

Every sector of every track.  Two diskettes with the same files
copied onto them with COPY are not the same to DISKCOMP, because the
files lie in different places; a diskette and its DISKCOPY are.

{b}The diskettes must match{p}

Both diskettes must be of the same kind.  Hard disks and network
drives cannot be compared.

{b}The exit code{p}

0 the same, 1 different, 2 stopped with Ctrl+C, 3 a track could not
be read, 4 the command line, the drives, memory, or diskettes of two
kinds.  With several comparisons, the last one's.
#examples
To compare the diskette in A: with the one in B:

    diskcomp a: b:

To compare two diskettes using one drive:

    diskcomp a: a:
#topic DISKCOPY|Diskcopy
Copies one diskette onto another, track for track.

{b}Syntax{p}

    DISKCOPY [drive1: [drive2:]] [/1] [/V] [/M]

{b}Parameters{p}

drive1:
    The drive with the diskette to copy.

drive2:
    The drive with the diskette to copy onto.  The same drive, or left
    out, means one drive: the source is read whole, and DISKCOPY asks
    for the diskette to write, as many times as you like.

{b}Switches{p}

/1
    Copies the first side only.

/V
    Reads each track back after writing it, to check it.

/M
    Keeps the copy in conventional memory, which means more than one
    pass for most diskettes.

{b}Related Commands{p}

To check a copy, see [[DISKCOPY]]'s partner [[DISKCOMP]].  To copy
files rather than a whole diskette, see [[COPY]] and [[XCOPY]].
#notes
{b}What it copies{p}

Everything, boot sector included: the copy is a diskette the same as
the first, bootable if it was.  Whatever was on the second diskette
is gone.

{b}Both of one kind{p}

The two diskettes must be the same kind.  A diskette that is not
formatted is formatted as it is written.

{b}The exit code{p}

0 copied, 1 a read or write error (the copy is finished as well as it
can be), 2 stopped with Ctrl+C, 3 the source could not be read, 4 the
command line, the drives, memory, or diskettes that do not match.
With several copies, the last one's.
#examples
To copy the diskette in A: to the one in B:

    diskcopy a: b:

To make several copies of one diskette with one drive, checking each:

    diskcopy a: a: /v
#topic DOSSHELL|Dosshell
Starts the PM-DOS Shell: the drives, directories, files and programs
in lists and menus, with the keyboard or the mouse.

{b}Syntax{p}

    DOSSHELL [/T[:res]] [/G[:res]] [/256]

With no switch, the shell starts the way it was last left.

{b}Switches{p}

/T[:res]
    Starts in text mode.  res is L for 25 lines or H for 50 (43 on an
    EGA).

/G[:res]
    Starts in graphics mode.  res is L for 25 lines, M1 for 30, M2 for
    34, H1 for 43 or H2 for 60.  L and H1 are 640 by 350 and run on an
    EGA; the others are 640 by 480 and need a VGA.

/256
    With /G:M1, /G:M2 or /G:H2: 256 colours.  Needs VBE 2.0.

{b}Related Commands{p}

For the commands the shell runs, see the [[Contents]].
#notes
{b}The screen{p}

A line of drives, the directory tree of the chosen drive beside the
files of the chosen directory, a list of programs in groups, and a
menu bar: File, Options, View, Tree and Help.  Long file names are
shown in every list.

{b}Running a program{p}

Choose a file or a program entry and press ENTER, or double-click it.
The shell runs one program at a time: there is no Task Swapper, as
PM-DOS does not swap programs.

{b}Settings{p}

The view, the colours and the program groups are kept in DOSSHELL.INI
beside DOSSHELL.EXE.
#examples
To start the shell in 50-line text mode:

    dosshell /t:h

To start it in graphics with 256 colours:

    dosshell /g:m2 /256
#topic EDIT|Edit
Starts the PM-DOS Editor, for making and changing text files.

{b}Syntax{p}

    EDIT [/B] [/H] [/R] [/S] [/nnn] [[drive:][path]filename ...]

{b}Parameters{p}

[drive:][path]filename
    The file to edit.  Several can be named, and wildcards name
    several.  A name that does not exist yet is a new file.

{b}Switches{p}

/B
    Black and white, for a monochrome screen on a colour card.

/H
    As many lines as the screen can show: 43 or 50.

/R
    Opens the files read-only.

/S
    Shows files by their short names.

/nnn
    Opens the files as binary, nnn bytes to a line (10 to 1024).

{b}Related Commands{p}

To look at a file without changing it, see [[TYPE]] and [[MORE]].
#notes
{b}The editor{p}

Up to nine files open at once, one or two windows, the File, Edit,
Search, View, Options and Help menus, cut and paste, find and
replace, and the WordStar keys.  F1 inside the editor explains them.

{b}What it writes{p}

Lines end with CR LF, and tabs are kept as tabs.  A file with LF line
ends is read, and written back with CR LF.
#examples
To edit a file:

    edit autoexec.bat

To open every .TXT file in the directory, read-only, in 50 lines:

    edit *.txt /r /h
#topic FC|Fc
Compares two files, or two sets of files, and shows where they differ.

{b}Syntax{p}

    FC [/A] [/C] [/L] [/LBn] [/N] [/T] [/W] [/nnnn]
       [drive1:][path1]filename1 [drive2:][path2]filename2
    FC /B [drive1:][path1]filename1 [drive2:][path2]filename2

{b}Parameters{p}

[drive1:][path1]filename1
    The first file.  Wildcards name several; each is compared with
    the second name, whose wildcards are filled in from the first.

[drive2:][path2]filename2
    The second file.

{b}Switches{p}

/A
    Shows only the first and last line of each set of differences.

/B
    Compares byte by byte and lists each byte that differs.  Files
    named .EXE, .COM, .SYS, .OBJ, .LIB and .BIN are compared this way
    unless /L says otherwise.

/C
    Treats capitals and small letters as the same.

/L
    Compares the files as lines of text.

/LBn
    Gives up after n differing lines in a row.  100 if not given.

/N
    Shows line numbers.

/T
    Keeps tabs as they are instead of expanding them to every eighth
    column.

/W
    Treats runs of spaces and tabs as one space, and ignores them at
    either end of a line and on lines with nothing else on them.

/nnnn
    How many lines must match before a difference is taken to have
    ended.  2 if not given.

{b}Related Commands{p}

To compare whole diskettes, see [[DISKCOMP]].
#notes
{b}How a text comparison is shown{p}

Each set of differences is shown under ***** and the file's name: the
last line that matched, the lines that differ, and the first line
that matches again.  When the files never match again within the
lines FC keeps, it says "Resync failed.  Files are too different".

{b}The exit code{p}

0 whatever the files hold; 1 only when a file could not be read or
the command line was wrong.
#examples
To compare two text files, with line numbers:

    fc /n old.txt new.txt

To compare two programs byte by byte:

    fc /b prog1.exe prog2.exe

To compare every .C file here with the copy in \BACKUP:

    fc *.c \backup\*.c
#topic FDISK|Fdisk
Sets up the partitions on a hard disk: makes, deletes, moves and
resizes them, and marks one active.

{b}Syntax{p}

    FDISK
    FDISK /STATUS
    FDISK /L
    FDISK /C d:p [n [tt]]
    FDISK /D d:p
    FDISK /A d:p
    FDISK /M d:p n
    FDISK /S d:p n
    FDISK /MBR d
    FDISK /GPT d
    FDISK /NOGPT d

FDISK on its own shows the disks and their partitions on the screen,
where they can be chosen and changed with the keyboard or the mouse.

{b}Parameters{p}

d:p
    Disk d, partition p.  Disks are numbered from 0, as the report
    shows them, so 1:1 is the first partition on the second disk.

n
    A number of sectors, or a size with M after it: 40M.

tt
    A partition type, in hexadecimal: 06 for FAT16, 0B for FAT32.

{b}Switches{p}

/STATUS
    Reports every disk's partition table.

/L
    The same report with the logical drives inside the extended
    partition walked.

/C d:p [n [tt]]
    Creates partition p on disk d in the largest free gap, or only n
    of it, and of type tt.

/D d:p
    Deletes the partition.

/A d:p
    Marks the partition active, so the machine boots from it.

/M d:p n
    Moves the partition so that it starts at sector n.

/S d:p n
    Resizes the partition to n sectors, or n megabytes written 40M.

/MBR d
    Writes a fresh master boot record on disk d, leaving the partition
    table as it is.

/GPT d
    Converts disk d to a GUID Partition Table (GPT).  Existing
    partitions and their files are kept.

/NOGPT d
    Converts GPT disk d back to an MBR partition table.  The disk can
    have no more than four partitions.

{b}Related Commands{p}

A new partition needs [[FORMAT]] before it can hold files, and [[SYS]]
to boot.
#notes
{b}A USB disk{p}

A USB disk is a disk of its own in the list, marked removable.  A
partition made, deleted or changed on it is used the next time its
drive letter is used, so no restart is asked for.  See [[USB]].

{b}The screen{p}

Each disk is a bar with its partitions drawn to scale.  A partition
can be chosen with the keyboard or clicked, and its edges dragged to
resize or move it.  Nothing is written until W writes the changes;
ESC throws them away.

{b}Resizing with files on it{p}

FDISK moves and resizes a partition with its file system inside, and
refuses when the files would not survive it.  Back the disk up first
all the same.

{b}Letters{p}

Drive letters are given out at boot: a partition made or deleted
changes the letters of the ones after it from the next boot on.

{b}GPT disks{p}

A GPT disk can hold up to 128 partitions, numbered 1 to 128, and all
of them are primary partitions.  GPT has no extended partition.  New
partitions start on a 1MB boundary, and FDISK updates both the
primary and the backup copy of the partition table.  Other versions
of DOS cannot see the partitions on a GPT disk.

Partitions past the first 2TB of a disk are shown but cannot be
changed, and PM-DOS does not give them drive letters.

/A marks the partition the computer starts from.  The boot code that
/MBR writes can start that partition on a GPT disk if the BIOS
supports the INT 13h extensions.

To convert a disk to GPT or back from the FDISK screen, press T.  A
disk with an extended partition cannot be converted to GPT, and a
partition in the first 34 or the last 33 sectors of the disk has to
be moved first.

{b}exFAT{p}

To format a partition from the FDISK screen, press F and choose FAT
or exFAT.  FDISK can show, format and delete exFAT partitions, but
cannot move or resize them.
#examples
To see every disk's partitions:

    fdisk /status

To make a 100MB FAT16 partition in the free space on the second disk:

    fdisk /c 1:1 100m 06

To make the first partition of the first disk the one that boots:

    fdisk /a 0:1

To convert the second disk to GPT:

    fdisk /gpt 1
#topic FIND|Find
Searches files for lines that contain a piece of text.

{b}Syntax{p}

    FIND [/V] [/C] [/N] [/I] "string" [[drive:][path]filename ...]

With no file named, FIND searches what is typed at the keyboard, or
what another command sends it through a pipe.

{b}Parameters{p}

"string"
    The text to look for, in double quotes.  Two quotes inside it
    stand for one.

[drive:][path]filename
    The files to search.  No wildcards: each file is named as it is.

{b}Switches{p}

/V
    Shows the lines that do NOT contain the text.

/C
    Shows only how many lines contain it.

/N
    Puts each line's number in front of it.

/I
    Capitals and small letters are the same.

{b}Related Commands{p}

To compare two files, see [[FC]].  To sort what FIND finds, see
[[SORT]].
#notes
{b}How the output looks{p}

Each file gets a heading: a blank line and ten hyphens and its name.
With /C the count is on that line.  Text from a pipe gets no heading.

{b}The exit code{p}

0 when any line contained the text (with /V, when any line did not),
1 when none did, 2 for an error.

{b}Capitals{p}

/I compares through the country's table of capitals, so accented
letters match their capitals too.
#examples
To list the lines of a file that mention a word:

    find "PATH" autoexec.bat

To count the lines of a listing that are directories:

    dir | find /c "<DIR>"

To number the lines that do not contain REM:

    find /v /n "REM" setup.bat
#topic FORMAT|Format
Prepares a disk for use: writes fresh file allocation tables and an
empty root directory, and on a diskette lays the tracks down.

{b}Syntax{p}

    FORMAT drive: [/V[:label]] [/Q] [/U] [/F:size] [/B | /S] [/C]
           [/FS:type] [/A:size]

{b}Parameters{p}

drive:
    The drive to format.  Everything on it is lost.

{b}Switches{p}

/V[:label]
    The volume label.  Without a label, FORMAT asks for one.

/Q
    Quick: the tables and the root directory only.  The data is not
    tested.

/U
    Unconditional: nothing of the old format is trusted.  A diskette
    has every track laid down again.

/F:size
    The capacity of the diskette: 160, 180, 320, 360, 720, 1.2, 1.44,
    1.68 or 2.88.  1.68 is DMF on a 1.44M diskette.

/B
    Accepted, and does nothing: SYS puts the system on afterwards.

/S
    Copies the system files afterwards, so the disk boots.

/C
    Tests the clusters an earlier format marked bad instead of
    keeping the marks.

/FS:type
    Formats the partition as FAT, FAT32 or EXFAT.  FAT gives FAT12 or
    FAT16, depending on the partition's size.  Hard disk partitions
    only.

/A:size
    Sets the cluster size: 512, 1K, 2K and so on, up to 32K for FAT
    and 32M for exFAT.  Hard disk partitions only.

{b}Related Commands{p}

To put the system on a disk that is formatted already, see [[SYS]].
To check a disk without losing what is on it, see [[SCANDISK]].
#notes
{b}A USB disk with no format{p}

A USB disk that has no file system - new, or with a partition FDISK
has just made - gets one laid out for its size: FAT12, FAT16 or FAT32,
with the cluster size MS-DOS and Windows would have chosen.  See
[[USB]].

{b}A disk that has a format already{p}

The layout is kept and the tables are written afresh.  Every data
sector is read back and the bad ones' clusters marked, unless /Q
skips the reading.  The boot sector is not touched, so a disk that
booted still boots.  A hard disk always gets this: there are no
tracks to lay down on an IDE disk.

{b}A diskette with no format, or the wrong one{p}

Every track is formatted and read back, and then the boot sector,
tables and root directory are written for the capacity asked for, or
the drive's own.

{b}exFAT{p}

/FS:EXFAT formats the partition as exFAT.  PM-DOS reads and writes
exFAT drives, with long file names that keep their case, but cannot
start from one.  Files of 4GB or more can be read but not written.
Other versions of DOS cannot read exFAT drives.

To change an exFAT drive back to FAT, use FORMAT /FS:FAT or
/FS:FAT32.

{b}Bad cluster marks{p}

Marks from an earlier format are kept, because somebody waited for
the test that made them.  /C or /U tests those clusters again.

{b}The exit code{p}

0 when the format was done, 1 otherwise.
#examples
To format the diskette in A: and label it:

    format a: /v:letters

To format a 720K diskette in a 1.44M drive:

    format a: /f:720

To make a bootable diskette:

    format a: /s

To format a hard disk partition quickly:

    format d: /q
